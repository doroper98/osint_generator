## 1. 원고 작성 절차

1. **리서치 → 사실 목록.** 사실마다 출처(매체, 날짜, URL)를 붙인다. 최신 사안은 반드시 웹 검색으로 확인한다. v3는 로이터, 코리아헤럴드, Foreign Policy, UPI, 국제해사기구(Seatrade 인용), 위키백과 "2026 Strait of Hormuz campaign"을 썼다.
2. **장면 설계(자유 구성).** 공간이 바뀌거나, 정보의 종류가 바뀔 때(지도→관계→연표→찬반) 장면을 나눈다. 장면 수를 미리 정하지 않는다.
3. **문장 작성.** 한 문장에 주장 하나. 날짜·주체·행위를 명확히.
4. **발음 텍스트 작성.** 숫자·기호가 있는 문장은 발음용 텍스트를 따로 쓴다(§5).
5. **린트 통과 → TTS 합성 → 타임라인 계산.**

## 2. 금지 문구 (AI 상투 문구) — 사용자 지정, 절대 금지

사용자 원문 목록:
- n가지 화살이 한곳으로 모인다.
- ㅁㅁㅁ가 한번에 흔들었다.
- 세겹의 문제가 눌려있는 지점.
- 앞으로 ㅁㅁㅁ가 ㅁㅁ의 방향을 정한다.
- 같은자리로 돌아온다.
- ㅁㅁ로 읽으면 이렇다.
- 그래서 이 카테고리 승부는 이제 화면이 아니라 공정에서 난다.
- 한국 부품 장비 회사에 이 발표가 진짜 뉴스인 이유도 거기 있다.
- 저 수준의 공정을 누가 대량으로 받아 주느냐가 다음 계약서에 그대로 적힌다.
- 서 있는 자리
- ~만 보면 ~로 읽힌다.
- ~이 말하는것, 그리고 말하지 않는것

이 문구들이 공통으로 가진 결함(새 문구를 판단할 기준):
1. **수렴 은유**("모인다", "한 점", "교차로"): 사실이 아니라 작가의 구도를 강요.
2. **과장된 동시성**("한번에 흔들었다"): 인과를 뭉갬.
3. **숫자 겹 은유**("세 겹", "n가지"): 목록을 신비화.
4. **예언형 결론**("방향을 정한다", "다음 계약서에 적힌다"): 근거 없는 전망.
5. **회귀 수사**("같은 자리로 돌아온다"): 내용 없는 마무리.
6. **해석 강요**("~로 읽으면", "~로 읽힌다", "~만 보면"): 독해를 대신함.
7. **가짜 대구**("말하는 것, 그리고 말하지 않는 것"): 형식만 있는 대비.
8. **"진짜 이유"류 메타 발언**: 앞 내용의 가치를 스스로 선언.

### 2.0 린트 면제 목록 (v5.17.0, back_and_forth D-0168, DECISIONS D162)
원고가 승인된 **뒤에** 생긴 문체·흐름 규칙(`rules script_grammar.lint_waivable` = uncertain-phrase·flow-sparse·flow-overuse·tense-present)에
걸린 승인 원고만 `projects/<pid>/lint_waivers.yaml`(git 추적, 항목마다 kind·sid·text_sha1·rule_since·script_approved·reason·decided_by)로
면제한다. (kind, sid, 문장 text sha1) **정확 일치**만 통과하고, 낡은 면제(오류가 없거나 원고가 바뀜)는 오류다. AI 상투 문구·출처·수치·발음 규칙은
면제할 수 없다. `script.plan`·`script.lint`(게이트 ① 화면) 같은 함수(`script/lint_waivers.py`), 게이트 ① 자료에 면제 표, provenance `features.lint.waived`.

### 2.1 린트 정규식 (v3 `plan3.py` `BANNED`)

### 2.2 좋은 문장의 형태 (v3 실제 문장)

## 3. 사실·균형 원칙

- **모든 수치에 출처.** 화면 카드에 출처 줄(`src`)을 넣는다(예: "로이터 · 대통령실 인용 수치", "국제해사기구 · 6월 11일 기준").
- **주장은 귀속한다.** "미군은 … 10억 배럴을 … 내보냈다고 밝혔습니다"(자체 발표), "~라고 보도했습니다".
- **논쟁 사안은 양쪽을 같은 무게로.** v3 찬반 패널: 지지(UPI 기고) 2항목, 반대(Foreign Policy) 3항목, 출처 명기.
- **민감 사건은 양측 주장 병기.** v1 사례:
  - 마이단: "우크라이나는 이를 '존엄 혁명'이라 부릅니다." / "러시아는 서방이 배후에 있는 쿠데타라고 규정했습니다."
  - MH17: JIT 결론 + "러시아는 이를 부인합니다"(화면 하단 노트).
  - 모스크바호: 우크라이나 "넵튠 미사일" / 러시아 "화재".
  - 카호우카 댐: "양측은 서로를 지목했습니다".
- **추정은 추정으로.** 번들 차트처럼 출처가 없으면 "추정 · 출처 미기재" 태그(`08` §9).
- **교차 검증.** 가능한 경우 외부 실측과 대조(v2: 번들 "18개월간 1%" ↔ DeepState 18.5%→19.3%).

> **v4.5.0 변경(사용자 결정 D85, CLAUDE.md C9, back_and_forth D-0096)**: 미검증·논쟁 문장의 검증 라벨(`<미검증>`·`<논쟁>`)은 영상 본문(자막·내레이션·카드·패널)에 넣지 않는다. 원고도 라벨을 쓰지 않는다(시스템이 claims status 로 계산해 `script_labels.json` 에 기록). 화면 표기는 엔딩 카드 맨 마지막 줄 가장 작은 글씨 한 줄(`rules layout_480p.end_card.notice_unverified`)뿐이다. 귀속("~라고 밝혔습니다")·양측 병기 원칙은 그대로다.

## 4. 자막 텍스트 vs 발음 텍스트

| 항목 | 자막(`text`) | 발음(`tts`) |
|---|---|---|
| 날짜 | 9월 18일 | 구월 십팔일 |
| 6월/10월 | 6월 17일 | **유월** 십칠일 / **시월** |
| 퍼센트 | 61% | 육십일 퍼센트 |
| 개수(고유어) | 14명 | 열네 명 |
| 건수(한자어) | 46건 | 사십육 건 |
| 연도 | 2009년 | 이천구 년 |
| 대단위 | 2만 명, 10억 배럴 | 이만 명, 십억 배럴 |
| 회담명 | 6자회담 | 육자회담 |
| 개월 | 18개월 | **십팔 개월** (고유어 금지) |

규칙:
- 발음 텍스트에는 **숫자·%·~·/·:·→·괄호·대괄호가 없어야 한다** (린트가 차단).
- 한자어 숫자는 **붙여 쓴다**: "백육십"(O) / "백 육십"(X, 연음이 깨짐, TTS-AP-058).
- 약어는 한국어 풀이로: "CENTCOM" → "미군 중부사령부", "IRGC" → "이란 혁명수비대". 자막에도 한국어를 우선.
- 강조어(`emphasis`)는 자막 텍스트의 부분 문자열이어야 한다(린트 검사).

### 4.1 강조 구간 계산 (`plan3.py` `build()`)
```python
segs = [[text, 0]]
for e in emphasis:                     # 앞에서부터 처음 1회만 분할
    ns = []
    for s_, f in segs:
        if f or e not in s_: ns.append([s_, f]); continue
        i = s_.index(e); ns += [x for x in ([s_[:i], 0], [e, 1], [s_[i+len(e):], 0]) if x[0]]
    segs = ns
```
렌더러는 segments를 글자 단위 플래그로 펼쳐 줄바꿈 후에도 강조가 유지되게 그린다(`09` §4).

### 5.4 문서에 추가할 신규 항목 (Claude Code가 반영)
- **TTS-AP-059 (신규)**: "개월" 앞 숫자에 고유어를 쓰는 오류. 저장소 `tts_of()`가 "18개월"→"열여덟 개월"로 변환함. 올바른 형태 "십팔 개월". `native_count` 적용 대상에서 `개월` 제외.
- **TTS-AP-060 (신규)**: 6월·10월 발음. "육월/십월"이 아닌 "유월/시월".
- **TTS-AP-061 (신규)**: 번들 `tts_of()`의 소수 처리 결과("팔십삼쩜구영딸러")가 된소리 표기를 섞음. 발음 텍스트는 표준 표기("팔십삼 점 구 달러")로 쓰고 된소리는 엔진에 맡긴다.

## 6. 음성 백엔드

### 6.1 edge-tts (현재 기본)
```python
edge_tts.Communicate(text, 'ko-KR-InJoonNeural', rate='-3%', pitch='-2Hz').save(path)
```
- 동시 5개(asyncio.Semaphore), 실패 시 4회 재시도.
- v1: InJoon 기본값, v2: rate -2%, v3: rate -3%, pitch -2Hz (차분한 다큐 톤).

### 6.2 ElevenLabs (사용자 커스텀 목소리 — 목표 기본값)
v3 `plan3.py` `eleven_one()`에 구현 완료, 환경변수 두 개가 있으면 자동 사용:
```python
POST https://api.elevenlabs.io/v1/text-to-speech/{ELEVENLABS_VOICE_ID}/with-timestamps
headers: {'xi-api-key': ELEVENLABS_API_KEY}
json: {
  "text": tts,
  "model_id": os.environ.get('ELEVENLABS_MODEL_ID', 'eleven_multilingual_v2'),
  "previous_text": 이전 문장 tts,   # 이어 붙일 때 억양 연속성
  "next_text": 다음 문장 tts,
  "voice_settings": {"stability": 0.65, "similarity_boost": 0.8, "style": 0.1}   # 저장소 HANDOFF 시작값
}
→ audio_base64 (mp3), alignment {characters[], character_start_times_seconds[], character_end_times_seconds[]}
```
- mp3와 `*.align.json`을 나란히 저장.
- 캐시 키: `sha1(tts + '|el|' + voice_id)[:10]` → 목소리를 바꾸면 전부 재합성, 문장만 고치면 그 문장만 재합성(과금 최소화).
- 분량: v3 발음 텍스트 1,839자 ≈ 5분 영상.
- 사용 가능한 모델은 `GET /v1/models`로 확인 후 한국어 지원 모델 선택.
- 발음 사전(pronunciation dictionary)은 요청당 최대 3개 연결 가능 → 인명·약어 고정용으로 추후 도입.
- API 키는 저장소에 커밋하지 않는다(`.env`, `.gitignore`).

### 6.3 글자 정렬을 단어 앵커에 쓰는 방법 (Claude Code 구현 과제)
v3 `at_word(sid, word)`는 자막 텍스트에서 단어 위치 비율 × 문장 길이로 추정한다. ElevenLabs 정렬을 쓰면:
1. `word`를 **발음 텍스트**에서 찾는다(인명·국가명은 자막과 발음이 같으므로 대부분 그대로 찾힌다).
2. 찾은 글자 인덱스의 `character_start_times_seconds`를 읽는다.
3. `t0 + (start − 트림 오프셋)`을 반환한다. 트림 오프셋 = 원본 mp3 앞 무음을 잘라낸 길이(§7에서 기록해 둘 것).
4. 못 찾으면 기존 비율 추정으로 폴백.

**v5.16.0 개정(사용자 결정 D151, D-0164·D-0165, DECISIONS D159)**: 정렬 파일이 **없으면 오류**다(`engine.timebase.AlignmentMissingError`).
비율 추정은 "단어가 발음 텍스트에 없음"(숫자를 읽기로 바꾼 자막 단어)에만 남는다. Supertonic 은 단어 시각을 내지 않으므로
`script.plan` 이 합성 직후 문장마다 강제 정렬(`script/tts/forced_align`, MMS_FA + uroman)로 `.align.json` 을 쓴다.
**정렬 참값의 정의**: edge `WordBoundary` 는 절대 시각이 아니다(TTS-AP-082 — 문장 시작 0.1초 고정, 쉼 앞 경계 = 쉼 시작, 문장 안 약 100ms 이름).
참값은 **음향 발화 시작**이다 — 원본 음성(44.1k mono)에서 `|a| ≤ silence_thr`(trim 문턱과 같음)가 `silence_sec` 이상 이어진 뒤
첫 초과 샘플, 그리고 문장 첫 소리. 참값 ↔ 정렬 어절은 순서·단조로 대응하고, 대응 없는 참값은 실패로 계상한다.
문장 안 어절은 edge 와의 **간격 차**로 검사한다(상수 치우침이 소거된다). 수치는 `rules tts_rules.forced_align` 한 곳(P3),
게이트 CLI = `python -m script.tts.align_gate`. 문턱 교차는 진짜 발화보다 10~20ms 늦다(참값 자체의 치우침 — 기준에는 반영하지 않음).

## 7. 음성 클립 후처리 (`plan3.py` `build()`)

```python
raw = ffmpeg -i mp3 -f s16le -ac 1 -ar 44100 -
a = int16 → float32 / 32768
idx = where(|a| > 0.012)
a = a[max(0, idx[0] - 0.03s) : idx[-1] + 0.12s]     # 앞 30ms, 뒤 120ms 여유
10ms 선형 페이드 인/아웃
np.save(npy); dur = len(a)/44100
```
정렬 사용 시 `trim_offset = (idx[0] - 0.03s)/SR`를 plan.json에 기록해야 한다(현재 미기록 → 추가 과제).

## 8. 타임라인 계산 (`plan3.py` `build()` 후반)

```python
GAP, SCENE_GAP, TITLE_CARD, END_CARD, LEAD = 0.5, 1.0, 5.6, 11.0, 1.2
t = LEAD
for 문장 x in 순서:
    if 장면이 바뀜:
        if 이전 장면 == 'open': 타이틀 카드 (t+0.2 ~ t+0.2+5.6); t += 5.6 + 0.6
        elif 이전 장면 있음: t += SCENE_GAP
        scene_start[장면] = t
    x.t0 = t; x.t1 = t + x.dur; t = x.t1 + GAP
t += 1.2; 엔딩 카드 (t ~ t+11); total = t + 11 + 0.5
```
- v1은 `EXTRA = {'C7_6': 17.0}`처럼 **문장 뒤 무음 구간**을 넣어 타임랩스를 보여 줬다. 시각 전용 비트가 필요하면 문장에 `after_gap` 필드를 두는 방식으로 일반화할 것.
- 타이틀 카드는 "콜드 오픈 장면 뒤"에 온다(v3). 콜드 오픈이 없으면 첫 장면 앞.

## 9. 자막 파일(SRT)과 유튜브 설명문

- SRT: 문장마다 `t0 → t1 + 0.15`, 텍스트는 자막 텍스트. 영상에 자막을 입혔으므로 SRT는 **자동 번역용**으로만 올리라고 안내(기본 자막으로 올리면 겹침).
- 설명문: 제목, 한 단락 요약, 챕터(각 장면 시작 시각 + 사람이 붙인 장면명), 자료 출처, 인물 사진 권리, 휘장·국기·지도·지형 출처, 음악 CC BY 표기, "내레이션: AI 음성 합성".
- 챕터명은 원고 장면에 `title` 필드를 두어 생성(v3는 렌더 후 수동 매핑).

## 10. 미디어 비트와 원고 (라운드 7)

## 12. v5.5.0 — 대본 서술 규약(script_grammar, 사용자 결정 2026-10-02 · 개정 2026-10-03, LLM-AP-013·014)

- **논쟁 주장은 막지 않고 양측을 밝힌다.** claims status 가 disputed 인 주장은 양측이 한 말을 귀속해 나란히 쓴다
  ("러시아는 ~라고 주장했습니다. 반면 나토는 ~라고 부인했습니다"). 양측 병기 자체가 논쟁 중임을 보여 준다(§3 그대로).
  말한 사람(귀속 표현 `script_schema.attribution_markers`) 없이 논쟁 주장을 사실처럼 쓴 문장만 린트 오류(`disputed-claim`).
- **출처마다 조금 다른 수치**는 출처를 붙여 쓰거나("AP통신은 약 80km라고 보도했습니다") 숫자 없이 쓴다. 수치가 쟁점의 핵심이면 양측 수치를 각각 출처와 함께.
- **내레이터의 미확인 결론 금지.** "엇갈립니다·아직 확인되지 않았습니다·정해지지 않았습니다"처럼 내용 없이 결론만 붙이는 문장은 오류(`uncertain-phrase`,
  패턴 = `rules script_grammar.uncertain_patterns`). 당사자가 그렇게 말한 것을 귀속해 전하는 문장은 된다.
- **문장은 흐름으로 잇는다.** 연결어(`rules script_grammar.connectives` — 프롬프트에 목록 그대로 노출)로 시작하는 문장 비율이
  `connective_min_ratio` 미만이면 오류(`flow-sparse`), `connective_max_ratio` 초과면 경고(`flow-overuse`). 인과 연결어는 실제 인과가 출처로 확인될 때만.
- **검사 시점**: 세 오류는 게이트 ① 진입 전에 막는다(`orchestrator/source_completeness_checker.BLOCKING`) — 승인 뒤 음성 단계에서 늦게 막히지 않는다.
- **마무리는 확인된 사실의 정리.** "아직 정해지지 않은 것"으로 끝내던 v3 관행(골든 `now_3`)은 폐기. 골든 원고는 고치지 않는다(테스트가 오류 2를 고정).
- 문안 SSOT = `rules script_grammar.lines` → 대본 프롬프트 `{{RULES.script_grammar}}`(P3).
