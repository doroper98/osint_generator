# 01. 피드백 로그와 설계 원칙

이 문서는 사용자(YK)가 세션 동안 준 **모든 요구와 피드백**을 시간순으로 기록한다. 원문은 가능한 한 그대로 옮겼다. 각 항목에 **해결 방식**과 **코드 위치**를 붙였다. 새 파이프라인은 이 목록을 회귀 테스트처럼 다뤄야 한다.

---

## 1. 라운드 0 — 첫 요청 (v1 제작 계기)

요지(원문은 세션 초반, 압축 전 기록):
- 러시아-우크라이나 전쟁의 **발단·전개·현재**를 다루는 유튜브 영상.
- **배경음악, 내레이션, 자막** 포함.
- 시각적으로 유려할 것. **우크라이나와 흑해 지도 중심**으로 어디서 무슨 일이 있었는지 보여 줄 것.
- 해상도 480p.

해결(v1):
- 흑해 권역 벡터 베이스맵 피라미드(200/100/50 ppd) + 카메라 이동.
- 7개 장(chapter) + 프롤로그/에필로그, 장 카드.
- DeepState 월별 점령지 스냅숏 61개로 2022.10~2026.9 타임랩스(17초 무음 구간).
- 자체 절차 합성 음악(D단조 진행, 강도 곡선, 붐·휘시 효과음).
- 결과: 8분 46초. 사용자 반응 "와 대단한데".

v1에서 확인된 데이터 판단(중요, `06` §6):
- DeepState 2022년 5~9월 스냅숏은 점령 레이어가 일부 빠져 러시아 통제 면적이 7~10%로 계산됨(실제 약 20%). **해당 구간은 사용하지 않고 개략 경계로 대체.** 2022.10 이후는 17.9%→19.3%로 외부 집계(약 19%)와 부합.
- DeepState는 2024년 쿠르스크 진격 지역을 표시하지 않음 → 개략 타원 ∩ 러시아 영토로 표시하고 "개략" 명시.

## 2. 라운드 1 — 보완 요청 (첨부 이미지 6장)

원문:
> 와 대단한데. 여기서 내가 보완 하고 싶은 부분이 있는데
> 1. 인물에 대한 표현 추가
> 2. 인물과 국기에 대한 표현 추가
> 2. 집단이나 단체, 정부기관 등에 대한 휘장 표현 추가
> 3. 그래프와 같은 차트에 대한 추가
> 4. 목소리에 대한 추가
> 5. 다른 르포 등 json 파일 활용에 대한 내용 추가
> 예를 들어 인물, 국기, 휘장들의 표현은 내가 첨부해준 이미지 처럼 보여주는거야.
> 목소리는 내가 만든 일레븐랩스 목소리가 있는데 그걸 활용하면 좋겠고, 르포 등 json같은 경우엔 이 링크같은자료가 있어.
> https://analysis-reports.pages.dev/analysis_20260829_115457_ec53e620b2.bundle.json

첨부 레퍼런스의 시각 문법(구현 명세의 원천, `07` §2):
- **인물**: 흑백 고대비 인물 컷아웃. 원형 플레이트 안에 국기가 펄럭이고, **어깨 아래는 원에 갇히고 머리는 원 밖으로 튀어나옴**. 아래에 검은 반투명 이름 라벨 박스 + 흰 굵은 글씨. (예: 스콧 베센트, 도널드 트럼프, 루슬란 크라우첸코)
- **기관/기업**: 원형 안에 휘장/로고 전체(예: 페트로브라스, 우크라이나 보안국 SBU). 원 테두리 + 아래 라벨.
- **국기/기구**: 지도 위 여러 원형 뱃지(EU, 미국, NATO, 우크라이나)가 관련 지역 근처에 배치.

해결: 설계안 제시 → 라운드 3에서 v2로 구현.

## 3. 라운드 2 — 저장소 분석 요청, 방향 확정

원문(요지 포함):
> 여기에 내가 영상을 만들 수 있는 요소들을 담아둔 저장소를 만들어뒀는데 너가 만든 영상의 완성도라던지 영상미 측면에서 훨씬 너가 만든게 우수한거 같아. … 어떻게 하면 내가 만든 저장소를 너가 만든 영상 만큼의 영상미와 완성도 측면을 끌어올리고 그리고 내가 만든 요소 중 일부라도 상속/계승 할 만한게 있는지 상세히 분석해.

분석 결론(상세는 `02` §3):
- 저장소는 **재료와 규율**(번들 어댑터, 권리 체계, 인물 라이브러리, TTS 정규화, 차트 정규화기)이 강함.
- 채팅 영상은 **촬영과 편집**(연속 공간, 카메라, 깊이, 크기)이 강함.
- 저장소 롱폼의 약점: 슬라이드형 장면, 11~17px 글자 다수(1080p 캔버스), 평면 배경, 정적 지도, 넓은 빈 공간.

이어진 사용자 결정 원문:
> 일단 내 저장소는 쇼츠는 만들지 않을꺼야. 깊이 있는 정보를 다루는 채널의 영상 제작으로써 기능 할꺼야. 그리고 해상도는 지금 내가 너와 트라이얼을 하는 기간이라 480p로 만들라고 한거야. 그 부분은 신경 쓰지 않아도 돼. … 이번에는 너가 직접 손으로 다 만들지 말고 저장소에서 너가 발견한 우수한, 상속 가능한 부분을 적용해서 만들어봐. … 나는 영상미 만큼은 너가 만든게 훨씬 우수하다고 생각해. 그 부분 감안해서 한번 만들어봐

→ **쇼츠(collage 브랜치) 트랙 폐기**, 롱폼 심층 채널 전용. 해상도는 최종 파이프라인에서 올린다.

## 4. 라운드 3 — v2에 대한 12개 지적 (가장 중요)

## 5. 라운드 4 — v3에 대한 피드백

원문:
> 거의 첫 씬에 "호르무즈와 한국" 이 두번 연속으로 나오는거 뺴고는 거의 마음에 들어. 목소리는 나중에 바꿀 수 있나?

원인: 타이틀 카드 뒤에서 카메라를 한국→걸프로 컷하려고 넣은 암전(dip)을 **모든 레이어 위**에 그려, 타이틀 글자까지 검게 사라졌다가 다시 나타남 → 두 번 나오는 것처럼 보임.

해결: dip 이벤트에 `under=True` 옵션 추가. 이 경우 비네트 직후·패널/카드/전면카드 **이전**에 그려 지도만 어두워짐. 타이틀은 연속으로 유지되고 배경만 바뀐다. (`render3.py` `render_frame()` dip 두 단계)

목소리 답변: 교체 가능. `plan3.py`에 ElevenLabs with-timestamps 경로 추가 완료(환경변수 `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`). 문장 앵커 구조라 재타이밍 불필요. 상세 `03` §6.

## 7. 피드백에서 도출한 설계 원칙 (Claude Code가 판단 기준으로 쓸 것)

### 7.1 구성
- 원고가 구조를 정한다. 번들 섹션 수, 템플릿 막 수가 정하지 않는다.
- 장면은 "새로운 공간 또는 새로운 정보 유형"이 필요할 때만 나눈다.
- 정보 화면(패널)은 지도에서 말하기 어려운 것(관계, 시간 순서, 찬반, 전례)에만 쓴다. 지도로 말할 수 있으면 지도로.

### 7.2 화면
- 모서리에는 날짜 하나. 그 외 고정 UI 금지.
- 휑한 화면 금지: 확대하면 라벨이 늘어난다. 패널은 화면의 70% 이상을 쓴다.
- 도장, 스탬프, 과장된 장식 금지. 라벨·선·뱃지로 정보만.

### 7.3 움직임
- 프레임이 완전히 정지하지 않는다(도착 후 드리프트, 국기 펄럭임, 펄스).
- 그러나 "여기서 저기로" 잦은 이동은 금지. 한 장면 한 이동.
- 선·요소는 천천히, 하나씩, 정돈되게. 동시 다발 등장 금지.
- 상태 변화는 내레이션 단어에 맞춘다(단어 앵커).

### 7.4 인물·기관
- 인물 = 흑백 컷아웃 + 국기 펄럭임 + 머리 팝아웃 + 이름/직함 라벨.
- 기관 = 실제 휘장(권리 확인), 국가 = 국기.
- 권리 제한이 있으면 추측으로 쓰지 말고 국기로 대체하고 기록한다.

### 7.5 원고·발음
- 사실 서술체. 수사적 결론, 반복 구조, 상투 문구 금지.
- 모든 수치에 출처. 논쟁 사안은 양쪽을 같은 무게로.
- 자막 텍스트 ≠ 발음 텍스트. 발음 텍스트에 숫자·기호가 있으면 실패.

### 7.6 오디오
- 음악은 들려야 한다(v3 이득). 내레이션이 항상 우선이지만 음악이 사라지면 안 된다.

### 7.7 확장성
- 목소리·해상도·주제가 바뀌어도 연출 코드를 고치지 않아도 되게(문장 앵커, 해상도 스케일, 데이터 주도).

## 9. 라운드 7 — 미디어 삽입을 표준 구성으로

> unclassified 영상과, 기사에 포함 된 경계 근무 사진, p-8 사진 잘 봤어. 잘 들어갔네. 그런 형태로 기사와 영상이 중간중간 들어가는 형태로 만들어지는 부분도 추가 해.

해결:
- 미디어 삽입을 시범이 아닌 **표준 구성(미디어 비트)**으로 규정: 러닝타임 40~60초당 1개, 장면당 1개 이하, 형태 섞기(`14` §10).
- v3에 추가: 이란 혁명수비대의 유조선 나포 자료 영상(war), 이라크 파병 한국군 자료사진(past), **기사 클리핑 카드** 2개(Reuters 9.4, The Korea Herald 9.7 — 헤드라인 번역, 핵심 구절 형광펜).
- 기사 화면 캡처 대신 자체 조판 카드(저작권), 매체 로고 미사용.

## 10. 라운드 8 — 품질 이전 가능성, 자동화, 오케스트레이터 관성

원문:
> 지금 영상의 퀄리티가 매우 매우 우수한데, 이걸 마크다운으로 osint generator 에게 전달 한다고 한들, 잘 작성할 수 있을까? 그리고 텔레그램에 osint 채널을 하나 만들어서 … 1080p 영상을 만들고 유튜브에 업로드 까지 가능하겠어?
> 그럼 osint generator 구조가 이미 내 명령을 받아서 claude 가 영상을 만드는 구조일텐데 맞지? 그럼 텔레그램과 자동업로드는 빼고 식별해야 할 영역에 대한 개선 계획은 다 잡힌건가?
> 근데 오케스트레이터의 고집이(코드가) 너무 세서 우리가 새로운 기능을 주입 해도 오케스트레이터에 기존에 주입 된 성향이나 관점에 따라 기능이 주입 되지 않는 경우가 agent reviewer 에 너무 많이 발생했어. 어떻게 해결할 수 있을까? agent reviewer 의 lessons learned 를 참고 해볼 수 있겠어?
> https://github.com/doroper98/agents_reviewer 여기야

결정·반영:
- 엔진은 문서+코드로 이전 가능. 편당 품질을 만든 **연출 판단+시각 검수**는 파이프라인 단계로 만들어야 한다 → `17`.
- 텔레그램 봇·유튜브 자동 업로드는 **이번 범위에서 제외**(엔진 안정화 후 별도). 자동 공개는 비권장, 두 번의 승인 + 비공개 업로드 권장.
- osint_generator는 이미 "사용자 명령 → 오케스트레이터 → `claude -p` 구독 브리지 워커" 구조 → 새 엔진은 scene_builder/render 자리를 교체 → `16`.
- 오케스트레이터 관성: agents_reviewer의 실제 사고(미배선 V5 게이트, CHART-AP-44 조용한 드롭, 모델 상수 override, 파국 폴백 9%, byte-equal 원칙)를 근거로 **주입 대신 교체** 원칙 수립 → `15`.
- 소스 인테이크(기사·X 게시물)와 게시물 카드 → `18`.
