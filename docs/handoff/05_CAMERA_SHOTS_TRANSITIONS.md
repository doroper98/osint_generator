## 1. 카메라 모델

상태 = (lon, v, w). v는 메르카토르 도 단위 위도, w는 화면 가로 경도폭.

```python
CAM = []   # (t, lon, v, w, dur, mode)
def cam(t, lon, lat, w, dur=3.0, mode='move'): CAM.append((t, lon, ym(lat), w, dur, mode))
```

### 1.1 프레임별 카메라 계산 (v3 `build_camera`)
```python
cams = sorted(CAM, key=t)
for i in range(N):                      # N = 총 프레임
    t = i / FPS
    while 다음 키프레임.t <= t:
        act = 다음 키프레임
        frm = 직전 프레임 카메라 if act.mode != 'cut' else act의 목표값     # cut이면 즉시 도착
    if act is None: v = 초기값; da = t
    else:
        e = ease_in_out_cubic((t - t0) / dur) if dur > 0 else 1
        lon = frm.lon + (lo - frm.lon)*e
        v   = frm.v   + (vv - frm.v)*e
        w   = exp(log(frm.w) + (log(ww) - log(frm.w))*e)      # ★ 로그 줌
        da  = t - (t0 + dur)                                  # 도착 후 경과
    if da > 0: w *= 1 - 0.03*(1 - exp(-da/9.0))              # ★ 도착 후 드리프트(천천히 3% 밀어 들어감)
```

- **로그 줌 이유**: 선형 보간이면 줌인 끝에서 급가속처럼 보인다. 로그 공간에서는 체감 속도가 일정하다.
- **드리프트 이유**: 화면이 완전히 멈추지 않게 한다. v1/v2는 7초 시정수 3.5%, v3는 9초 3%(더 차분하게).
- **이징**: `4x³ (x<0.5), 1 − (−2x+2)³/2` (ease-in-out cubic).

### 1.2 v1/v2의 줌 범프 — v3에서 제거 (지적 8)
```python
# v1/v2 (제거됨)
dist = hypot(lo - frm.lon, vv - frm.v)
peak = max(frm.w, ww, dist*1.25)
bump = (peak - max(frm.w, ww)) * sin(pi*e)      # 먼 이동일수록 중간에 크게 줌아웃
w += max(0, bump)
```
항공 촬영처럼 떠올랐다 내려앉는 효과는 멋있지만 **자주 쓰면 정신없다**는 피드백을 받았다. v3는 범프 없이, 먼 거리는 암전 컷으로 대체했다. 범프는 "여정 자체가 이야기"인 경우(비행 경로를 따라가는 한 번의 이동)에만 옵션으로 허용한다.

## 2. 숏 문법 (v3 규칙 — 사용자 합격 기준)

| 규칙 | 값 |
|---|---|
| 장면당 카메라 이동 | **1회**(예외: 광역→확대처럼 같은 권역에서 한 번 더) |
| 한 숏의 최소 머무름 | 6~8초 이상 |
| 이동 시간 | 2.6~3.4초 (ease-in-out, 로그 줌) |
| 이동 시작 시점 | 해당 문장 시작 0.6~1.2초 **전** (말이 나올 때 이미 도착 중) |
| 원거리 전환 | 0.5초씩 어두워졌다 밝아지는 **암전 컷**(총 1.0초) |
| 암전 빈도 | 5분 영상에 3회(v3). 90초에 1회 이하 권장 |
| 타이틀 카드 | 카드 뒤에서 컷(암전은 카드 **아래**에만) |
| 엔딩 | 느린 풀백(9초 동안 w 88→96) |
| 줌 범프 | 사용 안 함 |

### 2.1 프레이밍 규칙
- 한 문단에 나오는 장소를 **모두 한 화면에** 넣는 w를 고른다. 문장마다 장소를 옮겨 다니지 않는다.
- 뱃지는 라벨 포함 높이가 R의 약 3.3배(머리 팝아웃 위쪽 R×1.2 + 원 + 라벨 44px) → 화면 위·아래 가장자리 근처에 두지 않는다(v3 하메네이 뱃지 위도 30.3→29.35로 내림).
- 우상단 카드 영역(x ≥ W−260, y 70~200)과 우상단 날짜 영역, 하단 자막 영역(y ≥ 410)에는 핵심 마커를 두지 않는다.
- 광역 티어 경계 때문에 카메라가 클램프되면 가장자리 장소가 화면 끝에 붙는다 → 뱃지는 장소에서 **화면 안쪽 바다 쪽**으로 오프셋(v3 울산/부산 국기 뱃지를 127.0E 31.3N로 이동).

### 2.2 w 선택 가이드 (480p)
| 용도 | w(경도 도) | 예 |
|---|---|---|
| 대륙 간 항로 | 88~96 | 호르무즈→울산 유조선 항로 |
| 대양·광역 정세 | 60~72 | v2 모스크바–호르무즈 연결 |
| 권역 | 20~30 | 동유럽 나토 전선 |
| 해협·전선 | 12~16 | 걸프, 돈바스 |
| 국가 | 6~8 | 한반도 |
| 도시권 | 3~5 | 서울(대사관), 키이우 |
| 시가지 | 2.5 이하 | v1 부차 |

## 3. 암전 컷 (dip)

```python
def dip(t):                                   # v3
    ev('dip', t - 0.5, t + 0.5)               # 1초 암전 이벤트
    cam(t, *CUT_TARGET.pop(0), dur=0, mode='cut')   # 정중앙에서 순간 이동
```
- 렌더 시 알파 = 0.93 × sin(π × 진행률) → 중앙에서 최대 93% 검정.
- 장면 경계(이전 장면 마지막 문장 종료 + GAP + SCENE_GAP 사이)에 배치: `dip(SC('review') - 0.55)`. 자막이 없는 구간이라 끊김이 없다.
- `CUT_TARGET` 큐 방식은 v3의 편의 구현이다. Claude Code는 `dip(t, lon, lat, w)`처럼 목표를 인자로 받게 바꿀 것(순서 실수 방지).

### 3.1 카드 아래 암전 (타이틀 중복 버그 수정)
```python
ev('dip', title.t0 + 2.4, title.t0 + 3.4, under=True)
cam(title.t0 + 2.9, lon, lat, w, dur=0, mode='cut')

# render_frame 내부
지도·라벨 그린 뒤(비네트 없음 — 라운드 6) → under=True dip → 패널 → 사진·영상 → 카드·기사 → 날짜 → 전면카드 → 자막 → under=False dip → 전체 페이드
```
**버그 경위**: v3 초판은 타이틀 카드 뒤 컷용 암전을 모든 레이어 위에 그려, 타이틀이 사라졌다 다시 나타남 → 사용자에게 "타이틀이 두 번 연속"으로 보였다. 전면 카드 위에 암전을 절대 겹치지 말 것.

## 7. Claude Code 개선 과제

1. **자동 프레이밍**: 장면에 등장하는 장소 목록 + 뱃지 크기 + 예약 영역(카드·자막·날짜)을 받아 w와 중심을 계산하는 함수 `frame_points(points, reserve)`.
2. **자동 전환 선택**: 이전 숏과 다음 숏의 (중심 거리 / 평균 w) 비율이 2.5 이상이거나 w 비가 6 이상이면 dip, 아니면 move.
3. **숏 머무름 검사**: 린트처럼 "6초 미만 숏"을 경고.
4. **해상도 독립**: w는 그대로, 화면 크기에 따라 s = W_OUT/w가 자동으로 변하므로 카메라 코드는 수정 불필요. 단 픽셀 오프셋(뱃지·라벨)은 `09` §2 스케일 적용.
   > **구현 메모(v3.6.0, D-0067)**: 스케일은 렌더 진입 장치 변환 한 곳(`translate(pad_x)·scale(k)`, k = H/480). 카메라·레이어·검사는 설계 좌표 854×480 그대로, 래스터(지도 ppd×k·인물·사진)만 장치 해상도로 준비한다.

> **구현 메모(v4.1.0, back_and_forth D-0076)**: 카메라 키·프레이밍·제안은 무대 월드 좌표 (x, y, w)로 계산한다(`engine/stage.py`, handoff 20 §2.3). 지도 무대에서 월드 좌표는 (경도, Mercator 도 단위)라 결과는 v3.3.0 과 비트 단위로 같다(camera_suggest 결과 JSON 동일). 로그 줌·드리프트·dip 은 그대로다.

> **구현 메모(v3.3.0, back_and_forth D-0058)**: 제안 엔진(`engine/camera_suggest.py`)은 **틀 안 최적화**다. 현재 카메라 w 가 속한 §2.2 용도 분류(`shot_grammar.w_guide`)의 하한(`camera.framing.context_w_min`) 위에서 장소를 다 담는 최소 폭·중심을 낸다. 현재 스케일 분류가 틀렸으면 제안이 그것을 고치지 못한다. 자동 적용은 하지 않는다(P8).

> **구현 메모(v4.11.0, back_and_forth D-0118 §1 — 변화 사다리·느린 푸시인)**: 한 지도 뷰가 오래 머물 때의 처방은 **뷰 전환이 아니라 같은 뷰 안의 '동기 있는 변화'**다.
> 같은 뷰가 `rules:pacing.static_window.window_sec` 를 넘으면 문장 내용을 따라 ① 마커·라벨 등장 ② 관계선 하나 ③ 뱃지·카드 ④ 강조 ⑤ 그래도 없으면 숏 이동 순으로 변화를 준다(연출 프롬프트 `{{RULES.pacing.static_window}}`, 문안 = `rules:pacing.static_window.ladder`).
> 검사 `static_window`(warning, `[static-window]`)는 지도가 보이는 구간(숏 무대 mercator, 전면 카드·패널 덮개 밖)의 모든 창에서 `change_kinds` 변화(이벤트 등장 t0·카메라 키)를 센다(`engine/pacing.py`).
> 걸린 범위에만 **느린 푸시인(creep)**: w 를 범위 길이에 걸쳐 `creep.w_ratio` 로 선형 축소, 범위 뒤 유지 — 다음 키의 이동이 줄어든 w 에서 출발해 흡수한다. §1.1 드리프트와 곱한다. 45초에 4 % 라 줌 범프(§1.2, G4-16)가 아니다. 이동 중에는 걸지 않는다.

> **구현 메모(v5.1.0, back_and_forth D-0121 §A — 시간축 축 스케일 고정, 사용자 피드백 D105)**: 시간축 무대(주 무대든
> 차트 아일랜드 카메라든)의 카메라 w(화면이 덮는 일수)는 **장면 단위로 고정**한다. 확대·축소는 영상 전체
> `rules:stage_timeline.axis_scale.w_changes_per_video_max` 회 이하(오프닝 뒤 작업 척도·중간 1회·엔딩 조망), 한 번에
> `w_change_ratio_min` 배 이상만. 장면 안에서는 중심 이동(pan)만 — 지도의 "문장마다 줌 금지"(G4-16)와 같은 원리다.
> 검사 `timeline_rescale`(hard, `[timeline-rescale] t w a→b (이유)`), provenance `timeline.w_changes[]`, 연출·수정 프롬프트
> `{{RULES.stage_timeline.axis_scale}}`. 코드는 w 를 고치지 않는다(P8) — 걸리면 연출을 다시 쓴다(fed_policy LLM 재연출, 데모 사람 연출 수정).
>
> **차트 아일랜드 카메라(v5.1.0 D-0126 Q1 A)**: 주 무대가 backdrop 이면 `stage: timeline` 숏은 무대 전환이 아니라
> 차트 아일랜드 뷰포트의 카메라다(무대 연속성 검사에서 빠진다, 축 스케일 검사는 그대로). 아일랜드 없는 보조 무대 렌더는 아직 없다(Q7 A).
