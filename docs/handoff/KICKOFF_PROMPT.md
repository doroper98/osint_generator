# osint_generator 전면 개편 — 착수 지시

## 0. 너의 역할
너는 이 저장소(osint_generator) 전면 개편의 구현 책임자다. 설계는 끝났다. 너의 일은 설계를 정확히 구현하고, 각 단계의 결과를 **영상(프리뷰)과 테스트로 증명**하는 것이다.

## 1. 왜 개편하는가 (취지)
- 이 저장소의 기존 영상 생성 기준은 **폐기 대상**이다. 섹션과 장면을 1:1로 대응시키는 슬라이드형 구성, 고정된 12막, 작은 글씨, 평면 배경, 정적 지도, 모서리의 브랜드·섹션 표기가 여기에 해당한다. 사용자가 이 기준에 명시적으로 불만을 표했다.
- 새 기준은 claude.ai 채팅에서 사용자와 7차례 피드백을 거쳐 완성한 **지도 중심 다큐 파이프라인**이다. 기준 작품은 v3 『호르무즈와 한국』이다. 사용자는 이 영상의 영상미와 완성도를 "매우 매우 우수"하다고 평가했다.
- 이 채널은 쇼츠가 아니다. **깊이 있는 정보를 다루는 롱폼 지정학 채널**이다.
- agents_reviewer에서는 새 기능을 오케스트레이터에 주입해도, 기존 코드의 관성 때문에 반영되지 않는 일이 반복됐다. **이번 개편의 핵심 목표는 같은 실패를 반복하지 않는 것**이다(docs/handoff/15).

## 2. 목표 (완료 정의)
1. 새 엔진으로 v3 영상을 **골든 기준과 동일하게 재현**한다(docs/handoff/golden/, 문장 앵커 기준 프레임 25장).
2. 한 프로젝트를 처음부터 끝까지 돌린다. 흐름은 "사용자 명령 → 오케스트레이터 → Claude 워커(claude -p) → 새 엔진"이다. 소스 인테이크, 원고, 음성, 자산, AI 연출, 시각 검수, 렌더, 오디오, 전달을 모두 거치며, 사용자 승인 게이트 2개를 포함한다.
3. 옛 영상 문법으로 돌아갈 **통로가 코드에 남아 있지 않다**. 레거시를 삭제하고 관성 방지 테스트 8종을 통과한다.
4. 사용자의 **ElevenLabs 커스텀 목소리**로 바꿔도 연출을 고치지 않고 싱크가 유지된다(문장 앵커 구조).
5. **해상도 독립** 설계다. 트라이얼은 480p, 최종은 1080p다.
6. 영상마다 provenance.json으로 **"이번 영상에 실제로 쓰인 기능"**을 증명한다. 합격 기준은 "기능 코드가 있다"가 아니라 "이번 영상에 쓰였다"다.

## 3. 범위 밖
- 텔레그램 봇 인테이크, 유튜브 자동 업로드는 엔진 안정화 이후 별도 계획으로 다룬다.
- 쇼츠 트랙(collage 콜라주)은 보관만 한다.

## 4. 반드시 지킬 원칙 (docs/handoff/15)
- **주입하지 말고 교체하라.** 새 엔진은 오케스트레이터 밖의 독립 패키지(CLI)로 둔다. 오케스트레이터는 얇은 어댑터로 호출만 한다.
- **옛 경로는 플래그로 남기지 말고 삭제하라.** archive 브랜치에 보존한 뒤 main에서 지운다. 대상은 scene_builder, hyperframes, remotion, 섹션=장면 로직이다.
- **규칙은 rules/video_rules.yaml 한 곳에서 만들어 모두가 읽게 하라.** 코드 안 프롬프트 상수는 금지한다. 모델명과 주요 수치도 한 곳에만 둔다.
- **프롬프트가 예시로 보여 주는 출력이 스키마를 통과하는지** 테스트로 강제하라.
- **조용히 버리거나 옛 스타일로 폴백하지 말고 실패시켜라.**
- **"기존 출력 불변(byte-equal)" 원칙은 이번 개편에 적용하지 않는다.** 기준은 v3 골든이다.
- **헌법 문서(CLAUDE.md, GOAL.md)의 영상 기준부터 새 기준으로 바꿔라.**
- **권한을 나눠라.** 장면 구성과 연출은 LLM과 사용자가 정하고, 렌더 수치와 검증·권리는 코드가 정한다. 코드가 "정규화"라는 이름으로 LLM의 구성을 옛 모양으로 되돌리면 안 된다.

## 5. 되돌리면 안 되는 것 (사용자 합격 판정 완료)
- reference_code/v3_hormuz_korea의 수치(두께, 알파, 타이밍, 색, 글자 크기)는 **근거 없이 바꾸지 않는다.**
- 다시 들여오면 안 되는 것:
  - 고정 막 구성
  - 모서리의 브랜드명, 섹션 번호, 섹션 제목(모서리에는 날짜만)
  - 도장
  - 비네팅
  - 문장마다 카메라 이동, 줌이 튀어 오르는 연출
  - 한꺼번에 튀어나오는 관계선
  - AI 상투 문구(docs/handoff/03 §2)
  - 발음 텍스트 안의 숫자와 기호
- **사실·권리·검증 원칙(GOAL G4, CLAUDE C9)은 계승한다.**
  - 출처 없는 수치 금지
  - 논쟁 사안은 양측을 같은 무게로
  - 자료사진·자료 영상 표기
  - 사실 장면의 AI 생성 금지
  - 권리 기록과 크레딧(엔딩 카드 유지)

## 7. 작업 방식
- docs/handoff/13의 Phase 순서를 따른다. Phase 0(관성 차단) → Phase 1(골든 재현) → 이후 순서대로.
- **각 Phase가 끝나면 멈추고 보고한다.**
  1. 변경 요약
  2. 테스트 결과
  3. 프리뷰 컨택트 시트(영상에 영향이 있는 Phase)
  4. provenance 요약
  5. 다음 Phase 계획
  내가 승인하면 다음 Phase로 간다.
- 판정 기준은 "프로 다큐로 보이는가"다. 코드 리뷰만으로 "적용됨"을 판정하지 않는다.
- **커밋 규칙:** `vX.Y.Z:` prefix와 VERSION 일치, 한 커밋에 한 의도, PR 생성 금지. 이번 개편은 v2.0.0부터 시작한다.
- API 키(ElevenLabs 등)는 `.env`에 두고 커밋하지 않는다.
- **결정이 필요하면 추측하지 말고 나에게 묻는다.**
  - 사용 제한이 있는 휘장(CIA·대통령 문장 등)의 사용 여부
  - GOAL 합격 기준 개정
  - agents_reviewer 번들 스키마 변경
  - GmarketSans 폰트 파일 커밋 여부
  - 기준 브랜치

## 8. 이번 세션의 첫 작업
1. 문서를 읽고, 이해한 **취지·목표·원칙·범위를 10줄 이내로 요약해 보고**한다. 착수 전 확인이다.
2. **기준 브랜치를 확인한다.** assets/library(인물 라이브러리)는 collage 브랜치에만 있다. collage에서 `overhaul/v2-map-engine`을 분기하는 방안을 제안하고 승인을 받는다.
3. 승인 후 **Phase 0**을 수행한다.
   - CLAUDE.md와 GOAL.md 개정
   - 레거시 archive 후 삭제
   - rules/video_rules.yaml 신설
   - 워커 프롬프트를 파일로 분리
   - 관성 방지 테스트 8종 작성
4. Phase 0 결과를 보고하고 멈춘다.
