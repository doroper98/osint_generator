# 20. 장르 확장 규약 — 지정학이 아닌 주제의 자유 제작

> 번호 안내: 19, 19a는 Claude Code(Fable 5.1)가 작성한 분석·실행 계획이다. 이 문서는 그 다음 번호인 20번이다.
> 사용자 요청(원문): "우리가 정한 규약에 맞는 영상이 아닌 주제의 영상 제작의 경우엔 opus 5.5 개별 요소들은 규약을 따르나 최대한 opus 5.5 가 자유롭게 만드는 그런 형태로 주문 할 수도 있어? 예를 들어 연방준비제도의 최근의 금리 정책이라던지 이런 분야는 지정학 분야의 영역이 아니잖아?"
> "지정학이 아닌 주제에 대한 자유로운 제작에 대한 상세한 지침을 만들어줘. 지금 개발 중인 claude code 에게 전달해서 개발하는데 반영하도록 할꺼야."

선행 문서: `15`(관성 방지), `17`(AI 연출가·시각 검수). 이 문서의 규칙은 두 문서를 전제로 한다.

---

## 0. 목적과 적용 범위

- 지정학 영상의 규약(`03`~`14`)은 지도가 무대인 영상을 전제로 만들어졌다. 지정학이 아닌 주제에 그대로 적용하면 두 가지 실패가 생긴다.
  1. 억지로 지도를 끌어오는 실패(금리 영상에 세계지도 배경)
  2. 차트를 한 장씩 넘기는 슬라이드 영상으로 되돌아가는 실패 — **이것은 사용자가 폐기한 "12막 문법"의 재발이다.**
- 이 문서는 모든 영상이 지키는 규약과, 주제마다 바뀌어도 되는 부분을 분리한다. 그리고 바뀌는 부분을 Opus가 자유롭게 설계하되 품질이 무너지지 않게 하는 절차를 정한다.
- 적용 대상(예): 통화·거시경제(연준 금리, 인플레이션), 금융시장(채권·환율·주식), 산업·기술(반도체·배터리 공급망), 기업·정책 해설, 과학·기술 해설, 지도가 핵심이 아닌 역사.

## 1. 규약의 세 층

### 1.1 불변 층 — 모든 영상, 예외 없음

| 영역 | 규칙 | 근거 |
|---|---|---|
| 사실 | 모든 수치·주장에 출처. 논쟁 사안은 양측을 같은 무게로. 추정은 "추정" 표시 | `03` §3, GOAL G4 |
| 원고 | 고정 막 구성 금지, 문장당 주장 1개, 금지 문구 린트, 자막 2줄 이내 | `03` §1~2 |
| 발음 | 자막 텍스트와 발음 텍스트 분리, 발음 텍스트에 숫자·기호 금지, 저장소 TTS 안티패턴 | `03` §4~5 |
| 권리 | 공개 라이선스 확인, 권리 레지스트리, 자료사진 표기, 사실 장면 AI 생성 금지 | `07`, `14` |
| 타이포 | IBM Plex Sans KR / Noto Serif KR / GmarketSans / IBM Plex Mono(한글 섞이면 Sans 폴백) | `09` §1 |
| 화면 | 모서리에는 날짜만, 도장 금지, 비네팅 금지, 판독 최소 크기(화면 높이 2%) | `09` §2·5·8 |
| 자막 | 번인, 강조어 금색, 헤일로 5.0 | `09` §4 |
| 오디오 | 음악 레벨(v3 이득), 더킹, 효과음은 사건·전환에만, −14 LUFS | `10` |
| 구성 요소 | 엔딩 카드(자료 및 출처), 미디어 비트(40~60초당 1개) | `09` §6.2, `14` §10 |
| 공정 | 원고 승인 → 프리뷰 승인 두 게이트, 결정적 검사 → 시각 검수 루프, provenance 기록 | `16`, `17` |
| 카메라 문법 | 연속된 무대 위의 카메라, 장면당 이동 1회, 숏 6초 이상, 먼 이동은 암전 컷 | `05` §2 |

### 1.2 장르 층 — 주제마다 바뀐다
- 무대의 종류(§2)
- 쓰는 시각 요소(패널·차트·다이어그램)의 목록
- 색의 의미(지정학: 대립=붉은색 / 거시경제: 인상=따뜻한 색, 인하=차가운 색 등)
- 뱃지 대상(인물, 기관, 기업, 지표)
- 데이터 출처와 표기 방식(§5)
- 미디어의 종류(공식 사진, 발표 영상, 기사, 게시물)

장르 층은 **장르 프로필 파일**(§3)로 정의한다. 한 번 정해진 장르는 다음 영상부터 재사용한다.

### 1.3 자유 층 — Opus 재량
- 장면 구성과 길이(내용이 정한다)
- 무대 위 배치, 카메라 경로, 정보를 드러내는 순서
- 기존 시각 요소의 조합
- 새 시각 요소 제안(§4의 절차를 거친다)

**원칙: 자유는 조합과 연출에 있고, 불변 층은 협상 대상이 아니다.** Opus가 불변 층을 바꾸고 싶다면 제안만 하고 사용자 승인을 받는다.

## 2. 무대 원칙의 일반화

지정학 영상이 좋았던 이유는 지도 자체가 아니라, **연속된 무대 위를 카메라가 움직이며 시청자에게 공간 기억이 쌓였기 때문**이다. 지정학이 아닌 주제도 같은 문법을 쓰되, 무대의 종류만 바꾼다.

### 2.1 무대 유형 카탈로그

| 무대 | 좌표 | 적합한 주제 | 카메라 이동의 의미 |
|---|---|---|---|
| **지도**(기존 `MercatorStage`) | 경도·위도 | 지정학, 무역로, 자원 | 공간 이동 |
| **시간축 캔버스**(`TimelineStage`) | x=시간, y=레인(지표별 띠) | 통화정책 역사, 인플레이션, 선거 주기 | 시간 이동(왼쪽→오른쪽이 기본) |
| **차트 벽**(`ChartWallStage`) | 추상 좌표 위 격자 배치 | 금융시장 전반, 자산 간 비교 | 한 지표에서 다음 지표로 |
| **흐름도**(`FlowStage`) | 추상 좌표 위 노드·링크 | 공급망, 자금 흐름, 정책 전달 경로 | 단계를 따라 이동 |
| **구조도**(`ExplodedStage`) | 추상 좌표 위 층·부품 | 기술 해설(배터리 셀, 반도체 공정) | 바깥→안, 부품→부품 |
| **문서 무대**(`DocumentStage`) | 긴 세로 두루마리 | 성명서·법안 비교, 정책 문구 변화 | 문단에서 문단으로 |

### 2.2 무대 선택 규칙
1. 영상마다 **주 무대 하나**를 정한다. 보조 무대는 최대 하나(예: 시간축 + 짧은 지도 삽입).
2. 무대는 **연속된 좌표계**여야 한다. 장면마다 새 캔버스를 띄우면 슬라이드 영상이 된다.
3. 보조 무대로 넘어갈 때는 암전 컷을 쓴다(`05` §3).
4. 패널(`08`)은 무대로 말할 수 없는 정보(찬반, 관계, 체크리스트)에만 쓴다.

### 2.3 엔진 추상화 (Claude Code 개발 과제)
현재 카메라와 `View`는 (lon, v=ym(lat), w)를 쓴다. 이를 **무대 무관 좌표**로 일반화한다.

```python
class Stage(Protocol):
    name: str
    bounds: tuple[float, float, float, float]      # 월드 좌표 x0, y0, x1, y1
    def to_world(self, **anchor) -> tuple[float, float]:      # 예: Mercator(lon, lat) / Timeline(date, lane)
    def render_base(self, ctx, view) -> None:                 # 배경(지형 래스터 / 시간 격자 / 빈 캔버스)
    def draw_labels(self, ctx, view, reserved) -> None:        # 무대별 LOD 라벨(도시 / 날짜·연도 / 노드명)
    def lod_rules(self) -> dict:                               # w(월드 폭)별 표시 규칙

camera: (x, y, w)  — w는 화면 가로가 덮는 월드 폭. 로그 줌·드리프트·암전은 그대로(05)
View(stage, cam) → to_screen(x, y)
```
> **구현됨(v4.1.0, back_and_forth D-0076)**: `engine/stage.py` — `Stage` 프로토콜(+ 역변환 `from_world`), `MercatorStage`, `rules registries.stages`, direction `stage`·`shots[].stage`, 결정적 검사 `stage_continuity`(§12 관성 체크). v3 골든 25컷 md5 동일로 확인. 아래 원문은 그대로 둔다.

- `MercatorStage`는 현재 코드를 그대로 감싼다. **이 리팩터 후에도 v3 골든 프레임이 동일해야 한다**(회귀 테스트, `15` §5 `test_provenance_e2e`).
- `TimelineStage`의 x축 척도: 선형(기본), 필요 시 구간별 압축(예: 2008~2019 압축, 2020~ 확대). 압축 구간은 화면에 물결 표시로 명시한다(정직성, §5.3).

> **구현됨(v4.3.0, back_and_forth D-0084·D-0085)**: `engine/stage_timeline.py:TimelineStage`(월드 x = 시작일부터 일수·압축 왕복, y = 레인, 세로 척도는 무대 고정 — `View` 분기, 지도 경로 불변), 눈금 LOD(연 → 분기 → 월 → 일), 압축 물결 + "압축" 라벨, 카메라 `{date, lane?, w}`·핀 `marker {date, lane}`, direction `stage_config.timeline`, 되돌아가기 경고 `[timeline_backtrack]`(숏 `reason`). 실증 `projects/fed_timeline_demo`. 위 원문은 그대로 둔다.

## 3. 장르 프로필 (`genres/<genre>.yaml`)

장르 층을 선언하는 파일이다. Opus가 새 장르를 만들 때 이 파일부터 제안한다.

```yaml
genre: macro_monetary            # 통화정책·거시경제
status: approved                 # proposed | approved (사용자 승인 후)
stage:
  primary: timeline              # §2.1
  secondary: [chart_wall]
  timeline:
    lanes:
      - {id: policy_rate, label: 기준금리, kind: step, unit: "%"}
      - {id: inflation,   label: 물가상승률, kind: line, unit: "% (전년 대비)"}
      - {id: events,      label: 사건, kind: pins}
color_semantics:
  hike: "#ff7a59"                # 인상 — 따뜻한 색
  cut: "#5aa9ff"                 # 인하 — 차가운 색
  hold: "#a9b0bd"
  target_band: "rgba(232,184,96,0.15)"   # 목표 범위 띠(금색 반투명)
primitives:                      # 이 장르에서 쓰는 시각 요소(레지스트리 id)
  reuse: [card, article, post, badge, versus, timeline_panel, checklist]
  new:   [rate_step_line, dot_plot, yield_curve_shift, statement_diff, target_band]
badges:
  people: from_library           # 라이브러리 인물(예: 제롬 파월, 케빈 워시 초상이 이미 있음)
  institutions: rights_check     # 중앙은행 휘장은 권리 확인 후(07 §5)
data_sources:                    # §5
  required_fields: [series_id, source, retrieved_at, transform, as_of]
narration:
  define_terms_once: true        # 점도표·기준금리 등 전문 용어는 첫 등장 때 한 문장으로 정의
  avoid: [투자 권유, 가격 예측 단정]
media:
  preferred: [official_photo, press_video, article, post]
qa_extra: [chart_honesty, series_limit_3, units_visible, as_of_visible]
```

> **구현됨(v4.2.0, back_and_forth D-0081·D-0082)**: 스키마 `schemas/genre_models.py:GenreProfile`, 로더 `genres/load.py`, 프로필 `genres/geopolitics.yaml`(approved — 현 파이프라인 선언)·`genres/macro_monetary.yaml`(proposed — 위 예시). 위 예시와의 대응 두 가지(D73): `timeline_panel` = 레지스트리 패널 kind `timeline`(별칭 없음), `new` 중 등록 전 요소는 `rules registries.primitives_planned`(proposed 프로필만 참조 가능). statement_diff 색 의미 `added`·`removed` 를 더했다. direction `genre` 키와 결정적 검사 `genre_elements`. 위 원문은 그대로 둔다.

### 3.1 참고 프로필 초안 (Opus가 첫 영상에서 확정)

| 장르 | 주 무대 | 대표 새 요소 | 색 의미 |
|---|---|---|---|
| `macro_monetary` 통화정책 | 시간축 | 금리 계단선, 점도표, 수익률곡선 이동, 성명서 문구 비교 | 인상=따뜻, 인하=차갑, 동결=회색 |
| `markets` 금융시장 | 차트 벽 | 다중 자산 스파크라인 벽, 상관 히트맵, 변동성 띠 | 상승=초록, 하락=붉은색(한국식이면 반대 — 프로필에 명시) |
| `industry_supply_chain` 산업·공급망 | 흐름도 | 단계 노드, 물량 흐름 두께, 병목 표시 | 국가/기업 진영색 |
| `tech_explainer` 기술 해설 | 구조도 | 분해도, 단면 확대, 공정 단계 애니메이션 | 재료·층별 색 |
| `policy_document` 정책 문서 | 문서 무대 | 조항 비교(삭제·추가 표시), 문구 강조 | 추가=초록, 삭제=붉은 취소선 |

**시장 색 관례 주의:** 한국 시장은 상승=붉은색, 하락=파란색, 미국 관례는 반대다. 장르 프로필에 한쪽을 명시하고 영상 안에서 섞지 않는다.

## 4. 새 시각 요소를 만드는 절차 (자유 층의 안전장치)

Opus가 기존 요소로 부족하다고 판단하면 새 요소를 만들 수 있다. 다만 agents_reviewer의 "만들었지만 안 쓰임", "조용한 드롭" 사고(`15` §1)를 막기 위해 다음 절차를 반드시 거친다.

### 4.1 절차
1. **제안**: 요소 이름, 목적(무엇을 보여 주는가), 데이터 모양, 기존 요소로 안 되는 이유.
2. **스케치 프리뷰**: 실제 엔진으로 렌더한 1~3컷(목업 이미지 금지 — 실제 렌더러로).
3. **사용자 승인**(프리뷰 게이트 ②와 함께 받아도 됨).
4. **등록**: 레지스트리 항목 + 스키마 + 렌더러 + 프리뷰 예제 + 테스트를 한 커밋에.
5. **사용**: 연출 파일에서 레지스트리 id로만 호출.

### 4.2 새 요소의 계약
```python
# engine/primitives/<id>.py
SCHEMA = <Pydantic 모델>                 # 데이터 모양. 프롬프트 예시와 파리티 테스트(15 §P4)
def draw(ctx, view, t, e, style) -> Reserved:   # 예약 영역을 반환(라벨 충돌 회피에 사용)
PREVIEW_FIXTURE = {...}                  # 레지스트리 예제 → 갤러리·회귀 테스트
```
필수 조건:
- 색·크기·폰트는 `style.py` 토큰만 사용(하드코딩 금지). 해상도 스케일(`09` §2)을 따른다.
- 불변 층(폰트, 도장·비네팅 금지, 판독 크기)을 지킨다.
- 등장 애니메이션은 기존 문법(0.4~0.6초 페이드·슬라이드, 요소는 하나씩)을 따른다.
- 결정적 검사(`17` §3) 항목을 추가한다(예: 차트 정직성).
- 데이터 검증에 실패하면 조용히 버리지 않고 실패한다(`15` §P6).

> **구현됨(v4.2.0, back_and_forth D-0081)**: 계약 `engine/primitives/__init__.py`(SCHEMA·COLOR_KEYS·draw·PREVIEW_FIXTURE), 이벤트 `{type: primitive, id}`, 레지스트리 `rules registries.primitives`·레이아웃 토큰 `rules primitives.<id>`, 양방향·토큰 AST 검사 `tests/anti_inertia/test_registry_complete.py`, 첫 요소 `statement_diff`(스케치 `tools/primitive_sketch.py`), 등록 요소 갤러리 `tools/element_gallery.py`. 위 원문은 그대로 둔다.

### 4.3 개수 상한
- **영상 한 편에 새 요소는 최대 3개.** 먼저 재사용을 검토한다. 요소가 무한히 늘면 품질 관리가 불가능해진다.
- 한 번 등록된 요소는 장르 프로필의 `reuse`로 옮겨 다음 영상부터 기본 목록이 된다.

## 5. 데이터와 차트 정직성 (지정학이 아닌 주제의 핵심 위험)

경제·시장 영상의 품질은 숫자의 정확성과 차트의 정직성에서 갈린다.

### 5.1 데이터 출처
- 1차·공개 출처 우선: 중앙은행 공식 발표, 통계기관(미국 BLS·BEA, 한국 통계청 KOSIS·한국은행 ECOS 등), FRED 같은 공개 데이터 저장소. **시리즈마다 이용 조건을 확인**한다(일부 제3자 시리즈는 재배포 제한).
- 시장 데이터(선물 가격에서 추정한 금리 확률 등)는 사업자의 독점 데이터인 경우가 많다 → 출처 명시가 가능하고 이용이 허용될 때만 쓰고, 아니면 보도 인용(기사 카드)으로 대신한다.
- 모든 데이터는 레코드로 남긴다:
```yaml
series_id: FEDFUNDS          # 예시
source: FRED (St. Louis Fed)
retrieved_at: 2026-09-26
transform: 월평균, 원자료
as_of: 2026-08               # 화면에 "2026년 8월 기준"
revision_note: 잠정치는 이후 수정될 수 있음
```
- 차트는 **데이터에서 직접 그린다.** 다른 매체 차트 이미지를 따라 그리거나 캡처하지 않는다.

> **구현됨(v4.3.0, back_and_forth D-0084·D-0086·D-0088)**: 레코드 `schemas/data_models.py:SeriesRecord`(위 필드 + unit·frequency·license·license_note·source_url·missing·values, 허용 목록 `rules data`), 로더 `data/series.py`(원자료 재적용 대조), 수집 `tools/fetch_series.py`, 커밋 레코드 FEDFUNDS·CPIAUCSL. `series` 이벤트가 레코드에서 직접 그린다(빈 달은 끊고 "자료 없음"). 원고 출처 `series:<id>` + 수치 대조 린트. 엔딩 카드 `auto: series`. 위 원문은 그대로 둔다.

### 5.2 전망·예측 표기
- 전망은 누구의 전망인지 귀속한다("FOMC 참가자들의 전망 중앙값").
- 점도표는 약속이 아니라 참가자별 전망임을 한 번 명시한다.
- 가격·금리 예측을 단정하지 않는다. **투자 권유로 읽힐 표현을 쓰지 않는다**(엔딩 카드에 "투자 권유가 아닌 정보 제공 목적" 한 줄).

### 5.3 차트 정직성 규칙 (결정적 검사로 자동 확인)
| 규칙 | 검사 |
|---|---|
| 막대 그래프는 0에서 시작 | 기준선 값 확인 |
| 축 생략·압축 시 물결 표시 + 라벨 | 압축 구간 메타데이터 ↔ 화면 표시 |
| 단위를 화면에 표시(%, %p, bp, 억 달러) | 라벨 존재 |
| %와 %p 구분 | 원고·차트 단위 대조 |
| 한 차트의 계열 수 ≤ 3 | 계열 수 |
| 이중 축은 양쪽 축 라벨·색 대응 명시 | 라벨·범례 |
| 로그 척도는 "로그 척도" 표기 | 메타데이터 ↔ 표기 |
| 기준 시점(as of) 표시 | 표기 존재 |
| 출처 줄 | 표기 존재 |

> **구현됨(v4.3.0, back_and_forth D-0084 작업 5·D-0087)**: `engine/honesty.py` — 위 아홉 규칙을 결정적 검사 네 개(`chart_honesty`·`series_limit_3`·`units_visible`·`as_of_visible`, hard)로. 적용 범위는 축 종류(`rules qa_checks.chart_targets`, 렌더러 모듈 `AXIS`), 해당 없음은 `n/a` 메모. 위반 주입 아홉 건 전부 hard. 위 원문은 그대로 둔다.

### 5.4 숫자 발음 (저장소 TTS 규칙 준수)
- %p·bp·소수점은 저장소 정책을 따른다(D6 확정 전까지 저장소 정책 유지, `19` 계획 참조).
- 예시 방향: "0.25%p 인하" → 발음 텍스트에 퍼센트포인트를 풀어 쓴다. "25bp" → "이십오 베이시스포인트" 또는 "영 쩜 이오 퍼센트포인트"(표기 방식은 D6 결정에 따름).
- 날짜는 FOMC 회의일처럼 정확히(`03` §4).

## 6. 무대별 카메라·연출 문법

| 무대 | 이동 | 확대 | 암전 컷을 쓰는 경우 |
|---|---|---|---|
| 시간축 | 왼쪽→오른쪽 시간 순이 기본. 되돌아갈 때는 이유가 있을 때만 | 사건 핀(회의일·발표일)에서 확대, 확대 시 일 단위 라벨 등장(LOD) | 수십 년 점프, 보조 무대로 전환 |
| 차트 벽 | 관련 지표끼리 인접 배치해 짧게 이동 | 한 차트로 들어가 핵심 구간 강조 | 벽의 먼 구역 |
| 흐름도 | 흐름 방향을 따라 이동 | 병목 노드 확대 | 공급망의 다른 대륙·다른 단계로 점프 |
| 구조도 | 바깥→안 | 단면 확대 | 다른 부품으로 전환 |
| 문서 무대 | 위→아래 | 바뀐 문구 확대 + 형광펜 | 다른 문서로 전환 |

공통: 장면당 이동 1회, 숏 6초 이상, 도착 후 드리프트, 요소는 하나씩(`05`, `08` §3).

**무대의 LOD:** 시간축은 넓게 보면 연도, 확대하면 월·일 라벨과 개별 회의 핀이 나타난다. 지도의 "확대하면 도시가 보인다"(지적 9)와 같은 원리다. 휑한 화면 금지는 모든 무대에 적용된다.

## 7. 원고 작성 차이

- **용어 정의:** 전문 용어는 첫 등장 때 한 문장으로 정의한다(예: "점도표는 FOMC 참가자들이 각자 예상하는 금리를 점으로 찍은 표입니다"). 두 번째부터는 정의하지 않는다.
- **인과는 귀속:** "금리를 올려서 물가가 내렸다"처럼 단정하지 않는다. "연준은 ~라고 설명했습니다", "~라는 분석이 있습니다"로 귀속한다. 경제 인과는 논쟁 사안인 경우가 많다(불변 층의 균형 원칙).
- **숫자 밀도:** 한 문장에 숫자는 2개 이하. 나머지는 화면(차트·카드)이 말한다.
- **금지 문구 린트는 동일 적용.** 경제 해설에서 흔한 상투어도 금지 목록 후보로 모은다(예: "시장은 ~를 주목하고 있다", "~의 향방이 관건이다", "~에 촉각을 곤두세우고 있다").

## 8. 미디어

- 중앙은행·정부 공식 사진·영상: **기관마다 라이선스가 다르다.** 미국 연방정부 저작물은 퍼블릭 도메인이지만, 연방준비제도 이사회 자료의 지위는 파일별로 확인한다(가정하지 않는다).
- 기사 카드·게시물 카드(`14` §9, `18` §5)는 그대로 쓴다. 경제 영상에서 특히 유용하다(성명서 발표 보도, 공식 계정 게시물).
- 지정학 영상의 지도 컷아웃에 해당하는 것은 **무대 위 사물 컷아웃**이다(예: 흐름도 위 반도체 웨이퍼, 구조도 위 셀 사진). 권리·자료사진 표기 규칙은 동일.
- 미디어 비트(40~60초당 1개)는 불변 층이다.

## 9. 시각 검수 루브릭 추가 항목 (`17` §4.2에 덧붙임)
1. 슬라이드처럼 보이는가(장면마다 새 캔버스, 차트가 한 장씩 넘어감) → **실패**
2. 무대가 연속적인가(카메라가 같은 좌표계 위를 움직이는가)
3. 차트가 정직한가(§5.3), 단위·기준 시점·출처가 보이는가
4. 숫자가 화면과 내레이션에서 일치하는가
5. 색 의미가 장르 프로필과 일치하는가(인상/인하, 상승/하락)
6. 전문 용어가 정의 없이 쏟아지는가
7. 투자 권유로 읽히는 표현이 있는가

```
길이: 내용이 정한다(고정 막 금지).
```

## 12. Claude Code 개발 과제 (구현 계획 반영용)

기존 Phase 순서(`13`, `19`)를 깨지 않도록, 지정학 파이프라인이 안정된 뒤에 붙인다.

### Phase G1 — 무대 추상화 (Phase 6.9 이후 권장)
- `Stage` 프로토콜, `MercatorStage`(현 코드 감싸기), 카메라를 (x, y, w) 월드 좌표로 일반화.
- **합격 기준:** v3 골든 프레임 25장 동일(회귀), provenance에 `stage: mercator` 기록.

### Phase G2 — 장르 프로필과 새 요소 파이프라인
- `genres/*.yaml` 스키마, 요소 레지스트리 확장(§4.2 계약), 요소 갤러리(프리뷰 예제 일괄 렌더), 파리티 테스트.
- **합격 기준:** 레지스트리 미등록 요소 사용 시 오류, 등록 요소마다 스키마·렌더러·예제·테스트 존재.

### Phase G3 — 시간축 무대와 차트 정직성 검사
- `TimelineStage`(레인, 핀, 구간 압축 표시, 시간 LOD), 데이터 레코드 스키마(§5.1), 차트 정직성 결정적 검사(§5.3).
- **합격 기준:** 공개 시리즈 2개로 시간축 프리뷰 렌더, 정직성 검사 위반을 일부러 넣으면 실패.

### Phase G4 — 첫 비지정학 영상
- `macro_monetary` 프로필 확정(사용자 승인), 새 요소 3개, 주문 템플릿(§11)으로 한 편 제작.
- **합격 기준:** 두 게이트 통과, 시각 검수 루브릭(§9) 통과, 사용자 판정 "슬라이드가 아니라 다큐로 보인다".

### 관성 방지 체크 (`15` 연계)
- 장르 확장이 지정학 파이프라인의 동작을 바꾸면 안 된다(골든 회귀).
- 비지정학 영상에서 차트가 장면마다 새 캔버스로 뜨는 구성을 결정적 검사로 잡는다(무대 연속성 검사: 장면 전환마다 같은 Stage인지, 카메라 좌표가 연속인지).
