# TTS Antipatterns

본 문서는 TTS 발음·억양·운율·자막-음성 일치 관련 안티패턴 카탈로그입니다. **append-only**.

각 항목은 [README.md](README.md)의 표준 포맷을 따릅니다. Phase 8에서 `workers/tts_qa_worker.py`가 본 목록을 기계 검사 항목으로 사용합니다.

## 가장 치명적인 Top 20 (사용자 우선순위)

1. `TTS-AP-001` — "16시"를 "열여섯 시"로 읽음
2. `TTS-AP-014` — "2차전지"를 "두 차 전지"로 읽음
3. `TTS-AP-013` — 약어를 일반 영어 단어처럼 읽음 (c-DN ↔ CDN 등)
4. `TTS-AP-016` — R&D, OEM 등 사내 약어 발음 불일치
5. `TTS-AP-021` — `/` 슬래시 문자를 그대로 읽음
6. `TTS-AP-024` — `→` 화살표를 "오른쪽 화살표"로 읽음
7. `TTS-AP-002` — 날짜를 점·하이픈 그대로 읽음
8. `TTS-AP-019` — 단위 (kg, kWh, V 등)를 약어 그대로 읽음
9. `TTS-AP-022` — `:` 콜론을 비율 문맥에서 그대로 읽음
10. `TTS-AP-038` — 파일 경로 / URL을 통째로 낭독
11. `TTS-AP-039` — URL을 통째로 낭독
12. `TTS-AP-023` — 괄호와 따옴표를 그대로 읽음
13. `TTS-AP-044` — 동일 영상 안에서 같은 약어를 다르게 발음
14. `TTS-AP-029` — 매 쉼표마다 똑같은 멈춤
15. `TTS-AP-030` — 모든 문장 끝 억양 동일
16. `TTS-AP-031` — 강조 위치 오류 (앞 명사에 기계적 강세)
17. `TTS-AP-049` — 사과/대응문을 광고 톤으로 읽음
18. `TTS-AP-050` — 임원 보고를 유튜브 쇼츠 톤으로 읽음
19. `TTS-AP-018` — 숫자와 단위 사이에 부자연스러운 분리
20. `TTS-AP-051` — 글 대본을 그대로 낭독

## 1. 숫자 / 시간 / 단위 / 순서

### TTS-AP-001 — 시간 표기 "16시" 오류
- **증상**: "16시"를 "열여섯 시"로 발음 → 즉시 AI 티.
- **나쁜 예**: 16시 → "열여섯 시"
- **좋은 예**: "오후 네 시" 또는 "십육 시" (공식 문맥)
- **자동 조치**: `pronunciation_ko.yaml`에 `"16시": "오후 네 시"` 매핑. 일정·공식 문맥은 "십육 시" 옵션 분기.
- **회귀 테스트**: pending
- **발견 버전**: v0.1.0
- **상태**: active

### TTS-AP-002 — 날짜 표기 (점·하이픈·슬래시)
- **증상**: "2026.05.19"를 "이천이십육 점 영오 점 십구"로 발음.
- **나쁜 예**: 2026.05.19 → "이천이십육 점 영오 점 십구"
- **좋은 예**: "이천이십육년 오월 십구일"
- **자동 조치**: 정규식 `\d{4}[.\-/]\d{2}[.\-/]\d{2}` 매칭 → "{년}년 {월}월 {일}일" 치환.
- **회귀 테스트**: pending
- **발견 버전**: v0.1.0
- **상태**: active

### TTS-AP-003 — 시각 콜론 표기
- **증상**: "09:30"을 "영구 콜론 삼십"으로 발음.
- **나쁜 예**: 09:30 → "구 콜론 삼십"
- **좋은 예**: "오전 아홉 시 삼십 분" 또는 "아홉 시 반"
- **자동 조치**: `\d{1,2}:\d{2}` → 자연어 변환.
- **회귀 테스트**: pending · **발견 버전**: v0.1.0 · **상태**: active

### TTS-AP-004 — 자정/정오/24시
- **증상**: "00:00" → "영영 시 영영 분".
- **좋은 예**: 자정 / 밤 열두 시. 12:00 → 정오.
- **자동 조치**: 특수 시각 사전 매핑.

### TTS-AP-005 — 분기·연도 표기
- **증상**: "1/4분기"를 "일 슬래시 사분기".
- **좋은 예**: "일사분기" 또는 "1분기".
- **자동 조치**: 정규식 `\d/\d분기` → "{a}{b}분기".

### TTS-AP-006 — 짧은 연도 표기
- **증상**: "25년"을 "이십오 년"으로만 발화.
- **좋은 예**: 문맥상 "이천이십오년" 또는 "이오년".
- **자동 조치**: 앞뒤 문맥에서 절대 연도가 명확하면 풀어서 발음.

### TTS-AP-007 — 수량 / 개수 (고유어 사용)
- **증상**: "3개"를 "삼 개", "2명"을 "이 명".
- **좋은 예**: "세 개", "두 명".
- **자동 조치**: 개수 단위(개/명/번/살/회) 앞 한자어 → 고유어 자동 치환.

### TTS-AP-008 — 시간 단위 (한자어 vs 고유어)
- **증상**: "2시"를 "이 시"로 발화.
- **좋은 예**: "두 시" (일상), "이 시" (공식 일정).
- **자동 조치**: 시각 매핑.

### TTS-AP-009 — "2차전지" 발음
- **증상**: "2차전지"를 "두 차 전지"로 발화. **대표적 AI 티**.
- **좋은 예**: "이차전지".
- **자동 조치**: 전용 발음 사전.

### TTS-AP-010 — 회차 표기
- **증상**: "1회차"를 "한 회차".
- **좋은 예**: "일회차".
- **자동 조치**: `\d회차` → 한자어 발음.

### TTS-AP-011 — 소수점 단위
- **증상**: "3.5kg"을 "삼 점 오 케이지".
- **좋은 예**: "삼점오 킬로그램".
- **자동 조치**: 단위 약어 사전 + 소수점 공백 제거.

### TTS-AP-012 — 화폐·인원 콤마
- **증상**: "3,000원"을 "삼 콤마 영영영 원".
- **좋은 예**: "삼천 원".
- **자동 조치**: 콤마 제거 + 자연수 발음.

### TTS-AP-013 — 약어를 영어 일반 단어로 읽음 (`c-DN` ↔ CDN)
- **증상**: 사내 약어 `c-DN`을 시각 정보 없이 듣는 사람은 CDN으로 오인.
- **좋은 예**: 첫 등장 시 풀네임 + 이후 통일된 발음.
- **자동 조치**: 발음 사전. 첫 등장은 풀네임으로 강제.

### TTS-AP-014 — `2차전지` 같은 도메인 고유어 오발음
- **상태**: superseded by TTS-AP-009.

### TTS-AP-015 — 알파벳 약어 분리 발음
- **증상**: "R&D"를 "알 앤드 디"로 발음.
- **좋은 예**: "알앤디".
- **자동 조치**: `pronunciation_ko.yaml`에 약어 단위 매핑.

### TTS-AP-016 — 사내 약어 발음 불일치
- **증상**: SimBD를 "심비디" / "심비디이"로 혼용.
- **좋은 예**: 영상 안에서 통일.
- **자동 조치**: 발음 사전 + 변경 시 전체 영상 재검사.

### TTS-AP-017 — 영어 단어 과잉 원어민화
- **증상**: simulation을 과한 원어민 발음.
- **좋은 예**: 한국 업무 현장의 외래어 발음 (시뮬레이션).
- **자동 조치**: 외래어 표준 발음 사전.

### TTS-AP-018 — 숫자와 단위 분리
- **증상**: "삼" + (pause) + "킬로그램".
- **좋은 예**: 붙여서 "삼점오 킬로그램".
- **자동 조치**: 숫자+단위 토큰을 한 phrase로 처리.

### TTS-AP-019 — 단위 약어 그대로 읽기
- **증상**: "5mm" → "오 엠엠", "220V" → "이백이십 브이".
- **좋은 예**: "오 밀리미터", "이백이십 볼트".
- **자동 조치**: 단위 약어 사전.

### TTS-AP-020 — 버전 / 등급
- **증상**: "Ver. 2.1"을 "버 점 이 점 일".
- **좋은 예**: "버전 이 점 일".
- **자동 조치**: 버전 패턴 정규식 + 자연어 변환.

## 2. 기호 / 구두점

### TTS-AP-021 — 슬래시 `/` 그대로 읽기
- **증상**: "A/B 테스트" → "에이 슬래시 비 테스트".
- **좋은 예**: "에이비 테스트".
- **자동 조치**: `/`를 문맥에 따라 "와", "또는", "부터", 또는 제거로 변환.

### TTS-AP-022 — 콜론 `:` 그대로 읽기
- **증상**: "1:1"을 "일 콜론 일".
- **좋은 예**: "일대일".
- **자동 조치**: `\d+:\d+` 비율 패턴 → "{a}대{b}".

### TTS-AP-023 — 괄호·따옴표 그대로 읽기
- **증상**: "고객사(OEM)"을 "고객사 괄호 오이엠 괄호 닫고".
- **좋은 예**: "고객사, 즉 오이엠".
- **자동 조치**: 괄호 패턴 → "즉" 또는 제거.

### TTS-AP-024 — 화살표 `→` 그대로 읽기
- **증상**: "14일→4일"을 "십사일 오른쪽 화살표 사일".
- **좋은 예**: "십사일에서 사일로".
- **자동 조치**: `→` → "에서 ~로".

### TTS-AP-025 — 물결표 `~` 그대로 읽기
- **증상**: "3~5일" → "삼 물결 오일".
- **좋은 예**: "삼 일에서 오 일".
- **자동 조치**: `~` → "에서" 또는 "부터".

### TTS-AP-026 — 하이픈 `-` 그대로 읽기
- **증상**: "A-1"을 "에이 하이픈 원".
- **좋은 예**: "에이 원".
- **자동 조치**: 식별자 안 하이픈은 제거.

### TTS-AP-027 — 불릿 / 별표 / 샵
- **증상**: "- 리드타임 단축" → "하이픈 리드타임 단축".
- **좋은 예**: 기호 제거.
- **자동 조치**: 줄머리 불릿(-, •, ※, *) 제거.

### TTS-AP-028 — 콜론을 목적 도입에서 그대로
- **증상**: "목표: 리드타임 단축" → "목표 콜론".
- **좋은 예**: "목표는 리드타임 단축입니다".
- **자동 조치**: `^.+?:` → "{앞}는/은 ..."

## 3. 운율 / 억양 / 강조

### TTS-AP-029 — 매 쉼표마다 동일 멈춤
- **증상**: 모든 쉼표에 1초 멈춤 → 보고서 낭독 톤.
- **좋은 예**: 의미 단위로 멈춤 차등.
- **자동 조치**: 쉼표 수 절반 이상 제거 후 TTS 호출.

### TTS-AP-030 — 모든 문장 끝 억양 동일
- **증상**: 문장 끝마다 같은 종결 톤.
- **좋은 예**: 결론·조건·연결을 구분.
- **자동 조치**: 종결 어미 분류 + SSML(가능 시) pitch contour.

### TTS-AP-031 — 강조 위치 오류
- **증상**: 문장 앞·숫자에 기계적 강세.
- **좋은 예**: 의미 단위 강세.
- **자동 조치**: 핵심어 마킹 후 SSML emphasis 적용.

### TTS-AP-032 — 부정문 강세 오류
- **증상**: "단순 자동화가 아닙니다"에서 "아닙니다"만 강조.
- **좋은 예**: "단순 자동화가"에 강세, 또는 대조 대상에 강세.
- **자동 조치**: 부정문 패턴 강세 사전.

### TTS-AP-033 — 비교문 강세 오류
- **증상**: "A가 아니라 B"에서 A에 강세.
- **좋은 예**: B에 강세.
- **자동 조치**: "아니라 X" 패턴 X에 강세.

### TTS-AP-034 — 원인-결과 운율 실패
- **증상**: 원인절과 결과절을 같은 무게로 읽음.
- **좋은 예**: 원인 낮게, 결과 선명하게.
- **자동 조치**: "때문에/이므로" 다음 문장 강조 상향.

### TTS-AP-035 — 의문 아닌데 끝 올림
- **증상**: "완료했습니다?"처럼 들림.
- **자동 조치**: 종결 어미 사전.

### TTS-AP-036 — 평서문인데 종결 하강 과함
- **증상**: 뉴스 종결음처럼 매번 떨어짐.
- **자동 조치**: pitch contour 약화.

### TTS-AP-037 — 조사·어미 약화 실패
- **증상**: "이 / 데 / 이 / 터 / 는"처럼 각 음절 동일 힘.
- **자동 조치**: 조사·어미 자동 weak emphasis.

## 4. 파일 / URL / 경로

### TTS-AP-038 — 파일 경로 통째 낭독
- **증상**: `C:\GBDN\SIMBD_V2\ENGINE` → "씨 콜론 백슬래시…".
- **좋은 예**: "해당 엔진 폴더".
- **자동 조치**: 경로 패턴 매칭 → 의미 요약으로 치환 + 자막 표시.

### TTS-AP-039 — URL 통째 낭독
- **증상**: `https://...`를 "에이치티티피에스 콜론 슬래시 슬래시…".
- **좋은 예**: "링크는 화면에서 확인해 주세요".
- **자동 조치**: URL 정규식 제거 + 자막 처리.

### TTS-AP-040 — 이메일 / 계정명 통째 낭독
- **증상**: `monosound09@gmail.com`을 문자 단위 낭독.
- **자동 조치**: 이메일·계정명 자막 처리.

## 5. 문체 / 어휘

### TTS-AP-041 — 문어체를 그대로 낭독
- **증상**: "본 과제는 ~ 통해 ~ 제고하고자 합니다".
- **좋은 예**: 짧은 평문으로 변환.
- **자동 조치**: 문어체 단어 사전 (`상기`, `하기`, `동`, `본`, `旣`, `限`) + 구어체 치환 규칙.

### TTS-AP-042 — 한자어 부사·서술 (`제고`, `유관부서` 등)
- **증상**: "효율성을 제고하고자 합니다" → 보고서 톤.
- **좋은 예**: "효율을 높이려는 것입니다".
- **자동 조치**: 사전 치환.

### TTS-AP-043 — 사람이 안 쓸 표현을 그대로 낭독 (`상기 내용` 등)
- **자동 조치**: 사전 치환.

## 6. 일관성

### TTS-AP-044 — 동일 영상 안 약어 발음 혼용
- **증상**: SimBD를 영상 안에서 "심비디" / "심비디이"로 혼용.
- **자동 조치**: 영상 단위 발음 사전 캐시 + 첫 등장 발음 고정.

### TTS-AP-045 — 자막 표기 vs 음성 발화 불일치
- **증상**: 자막 "16시", 음성 "열여섯 시".
- **자동 조치**: 자막 / 음성용 텍스트를 별도 필드로 분리. `scene_manifest.caption` ≠ `narration_segments.normalized_text`.

## 7. 화면-음성 동기

### TTS-AP-046 — 발화 속도와 화면 전환 불일치
- **증상**: 차트 등장 전에 설명 종료, 또는 화면에 없는 정보를 설명.
- **자동 조치**: scene_manifest 기반 음성 segment를 scene 길이에 맞춰 재타임.

### TTS-AP-047 — 표 / 차트를 그대로 낭독
- **증상**: "구분 콜론 현행 콜론 개선" 등.
- **좋은 예**: "리드타임은 기존 14일에서 4일로 줄었습니다".
- **자동 조치**: 표 셀을 문장으로 변환하는 사전.

## 8. 호흡 / 믹싱

### TTS-AP-048 — 호흡 누락 또는 과잉
- **증상**: 무호흡 낭독, 또는 매 문장 인위적 흡기음.
- **자동 조치**: SSML break 시간 균형 또는 후처리에서 자연 호흡 삽입.

## 9. 사회적 톤

### TTS-AP-049 — 사과/대응문을 광고 톤으로
- **증상**: "불편을 드려 죄송합니다"가 밝게 들림.
- **자동 조치**: 문장 분류 (`apology`, `notice`, `briefing`) → 톤 프리셋 적용.

### TTS-AP-050 — 임원 보고를 유튜브 쇼츠 톤으로
- **증상**: 결론 강조가 광고 톤.
- **자동 조치**: 보고형 프리셋 (낮고 안정, 결론 직전 짧은 pause).

## 10. 대본 자체 문제

### TTS-AP-051 — 글 대본을 그대로 낭독
- **증상**: PPT 문장이 음성 대본으로 그대로 들어감.
- **자동 조치**: Script Agent 출력에 `is_speakable: bool` 검증 + 자동 구어체 변환 단계.

### TTS-AP-052 — 너무 완벽한 발음
- **증상**: 모든 음절 과도하게 명확, 사람 같지 않음.
- **자동 조치**: 매우 약한 음향 변조 (룸톤 0.5% 가량) 후처리.

### TTS-AP-053 — 너무 사람 흉내 (감탄·웃음 과잉)
- **증상**: 사과문에서 갑작스러운 웃음.
- **자동 조치**: 후처리에서 감탄사·웃음 제거.

## 부록 A — 표기 해석 오류 운영 규칙 (v0.16.0, 사용자 제공 실무 리스트 정리)

사용자 실무 리스트(50+항목)를 본 시스템의 **두 갈래 방어**로 흡수했다:

- **(1) 생성 단계 차단** — `workers/script_worker.py` system prompt 의 "TTS 발음 안전 규칙".
  LLM 이 narration 을 처음부터 발화형 한국어로 쓰게 한다 (약어→한국어 명칭/음차, 단위·날짜·
  시각·범위·기호 풀어쓰기, 영문/기호는 caption 에만).
- **(2) 자동 검출** — `orchestrator/tts_lint.py:lint_narration` + CLI `lint-script`.

## 6. 백엔드별 misread (정확한 한국어 표기조차 잘못 읽음) — v0.34.10

정확한 한국어 표기가 lint 를 통과해도 ElevenLabs 같은 백엔드가 한국어 음운 규칙을 잘못
적용해 자막과 발음이 어긋난다. lint 로 차단 불가(원본 표기에 잘못 없음). **발음 사전
(`orchestrator/tts_pronounce.py` + `*/assets/pronounce.json`)** 으로 narration 직전
음차 치환 — subtitle 은 원본 한글 유지.

### TTS-AP-054 — 외래어 / 한자어 misread (경음화 누락)

- 사례: "달러" → [딸러] 가 정상 broadcast 발음인데 [달러] 평음.
- 사례: "유가" → [유까] 가 정상인데 [유가] 평음.
- 픽스: `pronounce.json` 에 `"달러": "딸러"`, `"유가": "유까"`, `"원유": "워뉴"` 같이
  매핑. narration 합성 직전 substring 치환. 자막은 원본 한국어 그대로.

### TTS-AP-055 — 한자어 숫자 misread (한자어/고유어 혼동)

- 사례: "102 달러" → [백두 달러] 또는 [백쥐 달러] 같이 한자어와 고유어가 섞임. 정상은
  [백 이 딸러] 또는 [백이 딸러].
- 사례: "12345" → 잘못 읽으면 자릿수 누락 또는 한자어/고유어 혼합.
- 픽스: `tts_pronounce.num_to_sino_kr(n)` 가 1~9999 한자어 풀이 ("102" → "백 이",
  "12345" → "일 만 이 천 삼 백 사 십 오"). `apply_pronunciation` 가 narration 의
  모든 1~8자리 정수를 자동 변환. 자막은 원본 숫자.
- 보충: 숫자 직후 한글 단위어 ("80달러", "19일") 사이 공백 1 칸 자동 삽입 — TTS 가
  단위 발음을 분리 적용하도록 prosody hint.

### TTS-AP-056 — 기호 % / $ / # narration 직접 사용

- 사례: "50%" 를 그대로 두면 일부 백엔드가 "퍼센트" 가 아닌 [픽센트] 등 오발음 또는
  영문 "percent" 로 코드 스위치.
- 픽스: `pronounce.json` 에 `"%": " 퍼센트 "` (앞뒤 공백 — 단위어 분리). 또는 cue
  텍스트에서 명시적으로 "퍼센트" 로 풀어쓰기.

### TTS-AP-057 — narration ↔ subtitle 텍스트 분리 누락

- 사례: 합성용 텍스트("팔 십 딸러") 가 자막에도 노출되어 시청자 가독성 손상.
- 픽스: `pronounce.json` 의 변환은 **narration 직전만** 적용. subtitle / caption 은
  원본 한글 보존 (시청자가 자막에서 "80달러" 로 볼 수 있도록).

### A.4 자동 검출되지 않는 misread — 누적 사전 운영

- `pronounce.json` 은 **append-only**. 새 misread 발견 → 매핑 추가 → 다음 PATCH 반영.
- 본 사이클(v0.34.x 영상미 재빌드) 의 hyperframes/demo 가 첫 사전 (`hyperframes/demo/
  assets/pronounce.json`). 본격 파이프라인 통합 시 `orchestrator` 가 project 별 사전 +
  공용 사전 로딩 패턴으로 확장 예정.
