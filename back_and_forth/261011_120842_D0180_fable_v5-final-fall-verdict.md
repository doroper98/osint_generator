## 2. 실측에서 드러난 것 3건(합격을 막지 않음 — 기록·후속)

### 2-1. 컨테이너 간 비결정 — 들리지 않는 꼬리에서 생김(정상, 기록)
- 45문장 중 **19문장**의 기록(`region_sec[1]`·`f0_start_hz`·`f0_end_hz`)이 Opus `final_fall_table.md` 와 다릅니다(예: open_1 구간 끝 3.580 vs 3.305, war_0 f0_start 168.6 vs 104.2). 입력 mp3 는 같습니다(위 SNR). 같은 입력 2회는 바이트 동일 45/45.
- 원인 실험: 입력에 **±1 LSB(16비트) 디더** 만 더해도 기록 45/45 변화, 구간 끝 39/45 변화(최대 0.5초). harvest 의 꼬리 유성 판정이 문턱에 걸려 있어 디코더·CPU 경로의 미세 차이로 뒤집힙니다.
- 들리는가: 구간 끝이 갈리는 꼬리의 에너지는 문장 피크 대비 **최대 −43.7 dB(중앙 −62 dB)** — 들리지 않습니다. 들리는 부분(−30 dB 게이트)의 끝 음 플랫폼 차 중앙 0.34 반음.
- 결론: **오디오·final.mp4 md5 는 컨테이너 간 일치를 기대하지 않는다**(R-0205 §3 의 md5 대조는 성립하지 않음; V3 때도 audio_qa 0.02 dB 차). 골든(영상) 25/25 는 영향 없음. run_log §2 에 한 줄 추가(§4).

### 2-2. 표의 f0 값은 단일 프레임이라 신뢰 불가 — 게이트 중앙값으로 다시 잰 결과
- `f0_start_hz`·`f0_end_hz` 는 프레임 하나의 값이라 옥타브 오차가 그대로 들어갑니다(open_0 213.8, ask_2 229.2 — 이 목소리의 중앙 f0 는 ~104 Hz).
- 게이트(유성 & 20 ms RMS ≥ 피크 −30 dB) 프레임의 첫/마지막 10개 중앙값으로 다시 재면: **들리는 끝 음 변화 중앙 −2.8 반음**(−1.2~−4.5). 선형 하강이 마지막 유성 프레임(들리지 않는 꼬리)에서 끝나므로, 들리는 부분은 구간의 중앙 58%(최소 30%)만 차지해 −4 반음이 다 들리지 않습니다. **시안 C 와 같은 논리라 사용자 승인 범위** — 바꾸지 않습니다.
- 보정 뒤 끝 < 시작: **41/45**(원본 37/45). 남은 4문장(open_3 "결론입니다" +1.3, route_3 "닿습니다" +1.5, now_0 +1.9, debate_3 +7.4 반음)은 원래 올라가는 문장입니다. 사용자가 전편 청취에서 지적하면 그때 "중앙값 기준 목표 하강(C+)" 시안을 냅니다 — 지금은 만들지 않습니다(P12).

### 2-3. 추적기 옥타브 오류가 합성에 그대로 들어감 — 실제 결함(작음) → v5.20.2
- 구간 안 **들리는 부분**(−30 dB 이상)에 f0 > 1.6×중앙 프레임이 **18문장·합 0.42초**(5~85 ms/문장).
- 증거: 같은 f0 로 재합성한 신호와 원음의 0~1.2 kHz 로그 스펙트럼 상관이 **이 프레임들에서 0.1~0.5**(정상 프레임 0.8~0.9) — 배음 간격이 2배로 합성된 것, 즉 5~45 ms 동안 한 옥타브 위 톤. 피크 대비 −9~−12 dB 로 들릴 수 있는 세기인 문장 7개: open_0, route_2, war_0, war_3, ask_0, timeline_1, debate_0.
- 사용자 청취 샘플 C 도 같은 논리로 만들었고 합격이었으므로 V5 합격을 막지 않습니다. 다만 후속 영상 전부에 들어가는 결함이라 작은 패치로 정리합니다.

## 3. 후속 지시 — v5.20.2 (순서: v5.20.1 light A 뒤, v5.21.0 B 앞. 사용자가 끝 "튐" 을 지적하면 즉시 앞당김)

1. **규칙** `tts_rules.prosody.final_fall.octave_clean: {enabled: true, ratio_hi: 1.5, ratio_lo: 0.6, gate_db: -30}` + `FinalFallRules` 하위 모델 extra=forbid.
2. **구현**(`prosody.final_fall`, harvest+stonemask 뒤·cheaptrick/d4c 앞): 문장 전체에서 (유성 & 20 ms RMS ≥ 피크×10^(gate_db/20)) 프레임의 f0 중앙값 `med`. 구간 s0..e 의 유성 프레임 중 f0 > ratio_hi×med 이면 ratio_hi×med 이하가 될 때까지 **/2**, f0 < ratio_lo×med 이면 ×2. 정리된 f0 로 cheaptrick·d4c·하강·합성(엔벨로프도 바로잡힘). 구간 밖 프레임은 손대지 않는다.
3. **기록**: `FinalFallRecord.octave_fixed_n`(optional) 추가. `f0_start_hz`·`f0_end_hz` 는 단일 프레임 대신 **게이트 프레임 첫/마지막 10개 중앙값**(§2-2 정의)으로 — `final_fall_table.md` 재생성(끝/시작 반음 열 의미 복구). 호환 방향(optional)이라 schema_version 그대로.
4. **테스트 ≥ 4**: 정리 함수 단위(f0 배열: 2배 프레임 → 반, 0.5배 → 2배, 정상 무변경, 구간 밖 무변경) · 규칙 상수 0 · 결정성 · 기록 필드.
5. **호르무즈**: 골든 25/25(영상 무관), 총길이 260.66 그대로, audio_qa 네 판정, 표 재생성, run_log 에 §2-1 한 줄("컨테이너 간 오디오 md5 불일치는 정상 — 꼬리 유성 판정 비결정, 들리지 않음") 추가.
6. **청취 자료**: 영향 큰 6문장(war_3, ask_0, ask_2, timeline_1, open_0, route_2)의 **C vs C-clean** 교차 mp3 1개 → Fable 이 듣고 판단(사용자에게는 필요할 때만).
7. **바꾸지 않는 것**: 구간 끝 정의(마지막 유성 프레임)·하강량 4 반음·구간 3글자·크로스페이드 — 사용자 승인 샘플과 달라진다. 구간 밖 바이트 동일 유지.

Fable 검증 프로토콜(미리 공개): 같은 측정 스크립트로 **구간 안 옥타브 프레임 0**, 그 자리 스펙트럼 상관 ≥ 0.7, 들리는 끝 음 변화 중앙 −2.5~−3.0 반음 유지, 비영향 문장 끝 음 ±0.5 반음 이내.
