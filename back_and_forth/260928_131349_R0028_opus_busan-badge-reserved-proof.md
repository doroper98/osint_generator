# 결정 요청 — 작업 4 부산 뱃지 증명: hormuz 연출 좌표를 실제 부산으로 되돌릴지

## 쟁점
D-0032 작업 4는 "15·16컷이 v3 골든과 달라지므로 expected_deltas 등재"를 전제한다.
실측하면 지금 hormuz 에서는 뱃지가 가려지지 않는다. v3 최종본이 이미 임시 조치로 뱃지를 **125.6E 22.3N**(남중국해, 실제 부산 아님)으로 옮겼기 때문이다(08 §10 "알려진 결함(임시 조치됨)", `direction.py:88`, reference `render3.py:229`).
그래서 RESERVED 회피를 넣어도 이 좌표에서는 15·16컷 픽셀이 바뀌지 않는다. 전후 차이를 만들려면 연출 좌표를 바꿔야 한다.

## 실측 근거
- `docs/handoff/reports/phase5/hormuz_25/frames/15_review_0.png`: 뱃지 원·라벨(약 x 735–815, y 213–275)이 Reuters 기사 카드(y 70–195) 아래에 따로 있다.
- `16_review_1.png`: "거론된 선택지" 카드(y 70–170)와 뱃지가 떨어져 있다.
- 실제 부산(약 129.0E 35.1N)은 이 카메라에서 화면 우상단, 카드 영역 안에 들어간다. 원래 결함은 이 경우다.

## 선택지
**A. 연출 좌표 유지(125.6E 22.3N), 회피 기능은 일반 기능으로 구현**
- 결과: 25컷 무변경(expected_deltas 등재 없음). 전후 증명은 scratch 사본(hormuz 복사본의 뱃지 좌표만 실제 부산)으로 `reserved_before_after.png` 두 장 + 겹침 0 스크립트.
- 위험: 영상 안의 "부산에서 출항" 뱃지가 계속 부산이 아닌 곳에 있다.
- 되돌리기: 필요할 때 B로 direction.py 한 줄.

**B. hormuz direction.py 뱃지 좌표를 실제 부산으로 바꾸고, 회피가 자리를 옮기게 함**
- 결과: 15·16컷이 v3 골든·Phase 5와 달라진다 → expected_deltas 등재(D-0032 문구대로). 사실 위치가 바로잡힌다.
- 위험: 연출(배치) 변경을 코드 단계에서 한다(P8: 배치는 LLM+사용자). 회피 결과 위치가 v3 합격 구성과 달라지고, 사용자 합격 판정이 없는 새 구도다.
- 되돌리기: direction.py 한 줄 + expected_deltas 항목 삭제.

## Opus 권고: A
- ① 되돌릴 수 있는 선택: A는 영상 무변경, B로 언제든 넘어갈 수 있다.
- ② 핸드오프: 08 §11-4 과제는 "충돌 검사·자동 오프셋 기능"이다. 합격 연출 좌표를 바꾸라는 말은 없다. C0 "사용자 합격 값 근거 없이 바꾸지 않는다".
- ③ 저장소 실측: 현재 좌표에서 겹침이 없어 D-0032의 전제(15·16컷이 달라짐)가 성립하지 않는다. expected_deltas 는 측정된 결함 교정 전용(D34·D35) — 지금 결함이 측정되지 않는다.
