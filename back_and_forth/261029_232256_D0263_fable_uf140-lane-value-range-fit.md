# 지시 — 레인 값 범위를 데이터에 맞춘다(UF-140 "변동이 크지 않은 데이터는 가로로 펼쳐진 직선으로밖에 안 보인다")

사용자 원문(2026-10-29): "그리고 금리 같이 변동이 크지 않은 데이터나 차트의 가로축을 그렇개 늘려버리면 그냥 가로로 펼쳐진 직선으로밖에 안보인다." 원장 UF-140(open → 이 D 의 ③ 으로 guarded).

## 1. 진단(감독 실측)
- 시간축 레인의 값 범위가 0 에서 "깔끔한 최댓값"(금리 0~5.5%, 물가 0~8.98%)로 잡혀 있다. 레인 높이 약 96px(480p)에서 0.25%p 계단은 약 4px — 보이지 않는다. 가로축 고정(UF-138)으로 13개월을 틀 폭에 펼치면 그 평평함이 더 드러난다.
- 정직성 규칙은 **막대만 0 기준**(`chart_honesty [bar-baseline]`)이다. 선·계단 그래프는 축 값이 보이면 값 범위를 데이터에 맞춰도 정직하다(20 §5.3 — 축·단위·기준 시점 표시). 지금의 0 기준은 규칙이 아니라 구현의 기본값이었다.

## 2. 할 일(한 커밋 한 의도)
① **레인 값 범위 = 데이터 맞춤**: `rules stage_timeline.lane_range` 신설 — `mode: fit`(선·계단·띠), 범위 = [min − pad, max + pad], pad = span × `pad_ratio`, 눈금은 `nice_mantissas` 로 반올림, **최소 폭 하한** `min_span: {"%": 1.0, "%p": 1.0, "bp": 50, 기본: 데이터 span}` — 0.25%p 를 절벽처럼 과장하지 않기 위한 하한(단위별 값은 제안 → decision_request). 막대(E4)는 그대로 0 기준. 범위는 **영상당 한 번** 정한다(레코드 전체 — as_of 뒤 전망 점 포함 — 를 보고). 축 값은 레인 위·아래 끝에 표시(지금처럼) + 중간 눈금 1~2개(`ticks_max`).
② 레인 축 값이 0 이 아닌 곳에서 시작하면 출처 줄 끝에 "축 범위 n~m%" 를 붙인다(코드, 정직성 표기 — 20 §5.3 "단위를 화면에 표시" 의 연장). `units_visible` 검사가 이 표기까지 본다.
③ **검사 `[flat-lane]` hard**: 레인 안 선·계단의 그려진 세로 폭(px) < 레인 높이 × `flat_lane_min_ratio`(제안 0.35) 이면 실패 — 값 범위가 데이터에 맞춰지면 자동으로 통과하고, 변동 자체가 거의 없는 데이터(진짜 수평)는 연출이 그 레인을 빼거나 사유를 적는다(이때는 경고로 낮추지 않는다 — 평평한 선을 넣는 것 자체가 사용자 지적이다). 콘티·프리뷰·전편 같은 키. 테스트 2. 원장 UF-140 guards → guarded.
④ 가로축(UF-138) 과의 관계: w 는 고정이다. 변동이 작은 레인은 세로 범위로 살린다. 가로를 줄여서 살리지 않는다.
⑤ econ 연출 재작업(D-0261 ③) 에 반영해 콘티 판 v2 에 포함. 프리뷰 컷 1장(금리 레인 계단이 보이는 것)을 R 에.

## 3. 하지 않는 것
- 막대 0 기준 규칙은 그대로. 로그 척도 금지(별도 결정 없이). 레인마다 다른 "같은 단위" 축척 금지(`[chart-world-split]`)는 그대로 — 같은 단위 레인은 같은 범위를 쓴다.
