# 결정 — NB28 1080p 클립은 **A. 최소 엔진 경로 + 도구 옵션, 1024×576**

D-0073 반영(f52e1e3, MAD 기준선 유지)·NB24(근거 3명 등재, 17명 근거 없음 목록 = 추측 금지 지킴)·NB21(프롬프트 규칙 + 파리티 테스트, LLM-AP-008) 확인.

## 판정: A, 1024×576
- "렌더 코드 변경 없음"(작업 12)의 취지는 480p 결과 불변이고, 그것은 MAD 0·md5 692f228e 로 증명한다(D-0073 과 같은 해석). 파일만 만들고 엔진이 안 읽는 것은 P5·P12 위반이라 B 보다 A 가 맞다.
- 크기: 16:9 정확 + 필요 폭(990px) 이상 + 용량 최소 = **1024×576**. 1280×720 은 용량만 크다.
- 판정 기준 ①(함수 한 곳·revert 한 번) ②(D60 래스터 장치 해상도, 지형 티어 `res_<프로파일>/` 선례, P6 폴백 금지) ③(원본 1920×1080 실측).

## 요건
1. `Assets.load_clip`: 기본 프로파일 = 지금 그대로(`{file}_480.npy`), 비기본 = `media/res_<프로파일>/{file}.npy`, 없으면 **AssetError**(폴백 없음). checks `media_upscaled` 는 그대로(1080p 에서 0 이 돼야 함).
2. `tools/media_fetch.py --res 1080p`: 같은 segment·fps·pix_fmt, 1024×576, `media/res_1080p/`. md5·크기·원본 source_hash 대조를 `reports/phase11/nb28_media.json` 에. 레지스트리 스키마 무변경(C 안 아님).
3. artifacts 에 npy 를 넣지 않는다(212MB×2). 복원 절차 = webm(이미 artifacts media_src 에 있음)에서 `media_fetch --res 1080p` 재실행 — ARTIFACT_README·run_log §0 에 한 줄, md5 로 재현 확인.
4. 증명: hormuz 1080p 프리뷰 3컷(클립 컷 포함) + checks `media_upscaled` 0, 480p 25컷 MAD 0·md5 692f228e, 새 테스트(프로파일별 경로·없으면 오류·1024×576 형상).
5. G3 7번 검증 방법 열의 `checks:media_upscaled` 는 그대로 유효.
