# 제작 시간 단축(사용자 결정 D187) — 저장소 전체 검증 규칙 + 렌더 프레임 비용 프로파일

**순서**: gulf_pact_2026 본영상(D-0187)을 먼저 끝낸다. 이 지시는 그 뒤, 사용자 영상 흐름을 막지 않는 틈에 한다.
지금 제작 중인 gulf 에는 적용하지 않는다(D187).

## 0. 사용자 의도
사용자 확인(이 세션 대화): "맞아. 그리고 … 단편적 규칙이 아니고 우리 전체 저장소를 통해 영상생성할때의 규칙이어야 한다."
→ 이 규칙은 감독·구현 세션 사이 약속에 그치지 않는다. **저장소에서 영상을 만드는 모든 경로의 검증 규칙**이다.
CLAUDE.md C8.3 이 정본이고, 아래 문서·도구가 모두 그것을 가리켜야 한다(값 복사 금지, 규칙 키·절 인용).

## 1. 검증 규칙을 저장소 전체에 배선
1. **pytest 마커** — `pyproject.toml` 에 `slow` 마커 등록(미등록 마커 = 오류, `--strict-markers`). 느린 e2e·렌더·골든 재현 테스트에 `@pytest.mark.slow`.
   빠른 묶음 `python -m pytest -q -m "not slow"` 이 목표 3~5분 안에 끝나는지 실측해 보고한다.
2. **골든 25컷 단독 명령** — 영향 테마(dark·light)만 골라 돌리는 한 줄 명령(기존 도구 재사용, 예: `tools/golden_compare.py` 또는 e2e 테스트 선택자)을 정하고 문서에 적는다.
3. **문서 동기화** — `back_and_forth/README.md` §6.3 테스트 기준선·검증 프로토콜, `WORKFLOWS.md`(영상 제작 흐름의 검증 단계), `docs/handoff/15` P12 의 "결과 확인" 문구, `FABLE_HANDOFF.md` §2 를 C8.3 에 맞게 고친다. 각 문서는 "C8.3(D187)" 을 인용한다.
4. **강제 장치(C 말미 "차단 메커니즘")** — 마커 누락을 잡는 가벼운 테스트 1개: 소요 시간이 큰 테스트 모듈 목록(실측 상위)이 `slow` 를 달았는지 확인. 과하면 결정 요청으로 대안 제시.
5. 보고에 하루 1회 전체 pytest 시점 기록 방식(보고서 머리말 또는 run_log 한 줄)을 제안한다.

## 2. 렌더 프레임 비용 프로파일(1회)
- `cProfile` 로 720p 100프레임(호르무즈, dark·light 각 1회 권장)을 재고 상위 3개 비용(지도 타일 합성·텍스트·뱃지·카드 등)을 보고서로 낸다.
- 가장 큰 1개만 고치는 안을 `decision_request` 로 올린다(P12 한 번에 하나, 조건: 골든 dark·light 25/25 무변화).
- 코어 증설은 사용자 환경 결정이라 안내 문장만 보고서에 넣는다.

## 3. 버전
문서·테스트 마커는 PATCH. 렌더 최적화는 결정 뒤 별도 버전.
