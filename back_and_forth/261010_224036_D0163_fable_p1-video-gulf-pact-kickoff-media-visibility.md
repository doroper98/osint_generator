## 2. 기사·사진이 안 나오는 원인(Fable 실측)과 P1-0 수정(파이프라인, v5.20.0 MINOR)
원인 4가지:
1. 미디어 등록이 손 단계라 빠지면 연출 후보 0(PIPELINE-AP-019). kaliningrad·valdai 는 등록 0 → 기사·사진 0. 호르무즈도 기사 2·사진 2·영상 2 뿐.
2. 연출 프롬프트에 **리터럴** "미디어 비트 40~60초에 하나, 장면당 하나 이하"(`prompts/director.md:112`, `genre_director.md:29`) — 규칙 파일에 없는 값(P3 위반)이고 기사까지 같은 상한에 묶인다. 기사 트리거 낱말도 5개뿐(`media_beats.triggers.article`).
3. 기사 카드의 프레스 사진은 권리 기록된 사진만(C9) — 통신사 사진은 못 쓰므로 기사가 블러 무대 위 글자만으로 나온다.
4. "0건이어도 막지 않는다"(사용자 결정 2026-10-05)가 조용한 빈약으로 이어졌다 — gate-view 요약이 있지만 사용자가 연출 전에 보지 못한다.

P1-0 수정(이번 영상 전에, 작은 변경 묶음):
- **규칙으로 이관(P3)**: `rules media_beats.density: {beat_gap_sec: [40, 60], per_scene_max: 1, article_per_min_max: 2, photo_target_per_min: 1}`. 프롬프트 두 곳의 리터럴은 `{{RULES.media_beats.density}}` 자리표시로 생성. **기사 카드는 미디어 비트 상한에서 분리**: 보도를 인용하는 문장(claims 출처 type article, confirmed)마다 기사 카드 후보가 있고, 연출은 그 문장에 기사 카드를 **써야 한다**(분당 `article_per_min_max` 까지, 넘으면 긴 쪽 우선). 안 쓰면 검사 `[article-unused]` warning(사유 필수).
- **미디어 계획 게이트(gate-view media)**: 연출 전에 문장별 표 — 인용 출처 · 기사 등록 여부 · 사진 후보(찾은 수/권리 통과 수/선택) · 사유. `photo_target_per_min` 미달이면 media_note 에 이유(검색어·결과·라이선스 탈락)를 **문장 단위로** 적어야 통과(조용한 0 금지, P6). 이 표를 **사용자에게 게이트 ① 자료와 함께 보낸다**(연출 전에 사용자가 본다).
- 기사 트리거 확장: `보도했다·전했다·밝혔다(매체 주어)·인용·에 따르면·보도에 따르면·기고·사설·단독·확인했다(매체)` — 규칙 파일 목록.
- 사진 소싱 풀(권리 통과가 쉬운 곳을 먼저): 미 국방부·DVIDS·CENTCOM(PD), Wikimedia Commons CC, 각국 정부 Flickr 중 CC BY 계정, NATO(CC BY-NC-ND 는 제외). `tools/media_fetch.py search` 가 이 풀 순서로 돌도록 검색 프리셋(규칙 `media_beats.sources_order`).
- 테스트 ≥ 6: 규칙 키 → 프롬프트 생성 바이트, 기사 후보 미사용 warning, 게이트 표 생성(문장 수 = 행 수), 0건 사유 없음 → 오류, 트리거 매칭, 소싱 순서.
- **선택지 B(사용자 결정 필요, Fable 이 묻는다)**: 기사에 실린 통신사 사진을 "보도 인용" 으로 기사 카드 프레스 사진에 쓰는 사용자 예외(D153 과 같은 방식, restricted 기록·크레딧). 결정 전까지는 A(권리 통과 사진만).
