# 결정 요청 — NB28 1080p 클립: 엔진 읽기 경로 한 줄이 필요하다 (작업 11 ↔ 작업 12 충돌)

D-0073 확인·반영(`f52e1e3`, hormuz 25컷 md5 = 기준선).

## 쟁점
작업 11 은 "원본 webm → 1080 폭 npy 재추출 → 1080p `media_upscaled` 0" 을, 작업 12 는 "렌더·엔진 코드 변경 없음" 을 요구한다.
실측하면 둘을 함께 만족할 수 없다.

| 실측 | 값 |
|---|---|
| 엔진이 클립을 읽는 곳 | `engine/assets.py Assets.load_clip` — **`media/{file}_480.npy` 고정**. 프로파일(`res`) 무관 |
| `media_upscaled` 판정 | `engine/checks.py` 가 `A.clips[file].shape[2]`(npy 폭)을 장치 폭과 비교 → 지금 480 < 675·990 |
| 원본 | `media/strikes.webm`·`niovi.webm` 둘 다 **1920×1080**(artifacts phase7 복원본, 레지스트리 source_hash 대조 가능) |
| 추출기 | `tools/media_fetch.process_clip` 이 레지스트리 `tool.params.scale`(480×270) 한 벌만 만든다 |
| 클립 길이 | 각 120프레임(5초). npy 크기 = 120 × 폭 × 높이 × 3 |

npy 를 더 크게 뽑아 두기만 하면 엔진이 읽지 않으므로 `media_upscaled` 는 2 그대로다. 파일만 만드는 것은 P5·P12(쓰이지 않는 기능) 위반이다.

## 선택지
- **A. 최소 엔진 경로 + 도구 옵션**(권고).
  `Assets.load_clip`: 기본 프로파일이면 지금과 같이 `{file}_480.npy`, 아니면 `media/res_<프로파일>/{file}.npy` 를 읽고 **없으면 AssetError**(지형 티어와 같은 규칙 — 480p 를 늘려 쓰는 폴백 없음, P6).
  `tools/media_fetch.py --res 1080p`: 같은 segment·fps·pix_fmt 로 `scale × k` 를 `media/res_1080p/` 에 쓰고, 레지스트리가 아니라 fetch 보고(`media_fetch_report`)·nb28_media.json 에 md5 기록.
  크기: 480×270 × 2.25 = **1080×607.5** 는 정수가 아니라 가로세로비가 바뀐다(h = w·shape[1]/shape[2] → 1080p 레이아웃 0.3px 차). 그래서 **1280×720**(16:9 정확, 332MB/클립) 또는 **1024×576**(16:9 정확, 212MB/클립, 필요 최대 990px 이상) 중 하나. 권고 1024×576.
  480p 경로·파일 무변경 → hormuz 25컷 MAD 0·480p md5 692f228e 유지. 1080p 프리뷰 3컷 + checks `media_upscaled` 0 으로 증명. 새 테스트: 프로파일별 경로·없으면 오류.
  위험: 1080p 렌더에 클립 npy 준비가 필수 단계가 된다(없으면 명시 오류 — 지형 티어와 같음). 되돌리기: revert 한 번.
- **B. 이번 Phase 는 추출만 하지 않고 기록만**. NB28 을 G1~G4 첫 커밋으로 넘긴다. `media_upscaled` 2 warning 유지. 위험 없음, 작업 11 의 NB28 항목 미완료.
- **C. 추출 스케일을 레지스트리 `tool.params` 에 두 번째 벌로 기록**(A 의 변형): variant 기록 위치를 레지스트리로. 스키마(`MediaAsset.tool.params`)가 바뀌므로 문서 05 동기화가 더 붙는다.
