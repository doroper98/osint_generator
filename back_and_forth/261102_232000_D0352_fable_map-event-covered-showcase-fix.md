## 배경
- 73713f0d 로 [map-event-covered] 가 sweet-galileo 에 들어왔다. 자라는·나타나는 지도 사건이 덮개 밑에 25% 넘게 가리면 실패한다.
- 속도 트랙이 v3 연출(2aab8e4d)로 잰 결과 showcase_geo 3건이다. 시트: artifacts/speed-pipeline-v7.4.0 ff4abf32 `map_event_covered_d1002/showcase_geo_redesign_2aab8e4d/`. 감독이 시트를 봤다. 셋 다 진짜다.
  1. act2_5 경로 '레일라호 · 7월·8월'(성장 96.0~106.5초)이 블라디보스토크 사진 밑에서 자란다(t=101.9, 88%).
  2. act4_1 폭발 boom(171.3~173.3초)이 지뢰 표지판·철책 2분할 사진 밑이다(84%). 자막이 바로 "9월 21일 오전, 서부전선 비무장지대에서 폭발이 일어났습니다" 다. 문장의 주인공이 가려진다.
  3. act2_1 마커 '극동'(84.5~86.5초)이 하바롭스크 사진 밑에서 나타난다(100%).
- 원칙은 UF-173 과 같다: **지도 사건이 먼저, 사진은 그다음**. 사진을 늘려 맞추지 않는다.

## 할 일
1. 세 건을 고친다. 우선순위는 이렇다.
   - 사진이 끝난 뒤 사건이 자라게 하거나(사건 시작을 같은 문장 안에서 늦춘다), 사건이 끝난 뒤 사진이 들어오게 한다.
   - 사진은 자기 날짜 창 안에서만 6초를 채운다(D-0349). 날짜 창 안에 자리가 없으면 그 사진을 뺀다.
   - 2번은 폭발이 먼저 보여야 한다. 사진은 boom 창 뒤에 들어온다. 같은 날짜(09.21) 창 안에서 두 사진 6초가 안 되면 철책을 빼고 지뢰 표지판 하나로 간다. 이때 [media-density] 가 7 아래로 떨어지면 decision_request 로 올린다. 규칙을 풀지 않는다.
2. 두 편 프리뷰 hard 0 을 확인한다. [map-event-covered] 를 포함한다. showcase_econ 도 이 검사 0 을 확인한다.
3. showcase_geo 콘티 판을 다시 렌더한다(v4_animatic). econ 은 바뀐 것이 없으면 그대로 둔다.
4. 고친 세 곳을 각각 10초 안팎의 짧은 mp4 로 자른다(UF-207). 콘티 판에서 자르되, 사진 자리 상자가 사건 뒤에 들어오는 것이 보여야 한다.
5. README §6.3a 대로 `tools/review_sheet.py`·`tools/uf_checklist.py` 를 geo(v4)·econ(v3)에 돌려 R 에 붙인다. 이 감독 컨테이너에는 projects/ 가 없다. 그래서 생성은 구현 세션이 한다. 점검표의 `[ ]` 는 네가 시트를 보고 채운다. 감독은 시트로 다시 대조한다.
6. 골든 25컷과 빠른 묶음 결과를 함께 적는다(병합 뒤 첫 확인).
