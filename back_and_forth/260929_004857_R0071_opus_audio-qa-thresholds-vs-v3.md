# 결정 요청 — 오디오 QA 임계와 v3 합격본 충돌(작업 6) · 문장 음량 정규화(작업 7)

D-0060 대로 hormuz v3 를 먼저 쟀다. 측정 코드는 `audio/qa.py`(검사기 하나). v3 최종 음성은 hormuz_camauto `out/final.mp4`(mix.f32 md5 `c1314fb9` = hormuz 와 같음)로 쟀다.

## 쟁점 1 — v3 합격본이 13 수치 둘을 벗어난다
| 항목 | 13·규칙 목표 | v3 실측 | Phase 1 보고(같은 방법) |
|---|---|---|---|
| 최종 통합 음량 I | −14 ± 1 LUFS | −14.23 | −14.23 |
| 트루 피크 TP | ≤ −1.5 dBTP | **−1.38** | −1.43 |
| 내레이션 구간 음악(+효과음) − 내레이션 | −18 ~ −14 dB | **−12.67** | −12.69 |
| 같은 값, 베드만(효과음 제외, 믹서 재구성) | | −12.82 | |
| mix 피크 ≤ master_peak 0.97 | | 0.887 | |

- **음악 레벨**: v3 는 13 범위보다 약 1.2 dB 크다. 10 §3.3 이력으로 v2 를 같은 식으로 환산하면(bed 0.33·덕킹 60% → 내레이션 중 실효 0.132 vs v3 0.235 = −5.0 dB) **v2 ≈ −17.8 dB 로 13 범위 안인데 사용자가 "너무너무 작다"고 거절**했다. 13 범위는 사용자 판정과 반대 방향이다.
- **트루 피크**: loudnorm(단일 패스, 동적) 뒤 AAC 인코딩에서 목표 −1.5 를 0.1 dB 남짓 넘는다. mix 는 무관하다(피크 0.887).

### 선택지
- **A(권고) 규칙을 사용자 합격본 쪽으로 명시 개정** — `audio.qa.music_under_narration_db: [-15, -11]`(v3 −12.8 중심 ±2, v2 −17.8 은 밖). 트루 피크는 mux 를 바꾸지 않고 판정만 `TP ≤ loudnorm.TP + 0.5`(코덱 여유, 규칙 `audio.qa.tp_codec_margin_db`). 둘 다 hard. 근거 주석에 10 §3.3 이력·이 실측을 적는다.
- **B 13 수치 유지, 오디오 항목은 warning** — v3 가 영원히 경고를 낸다. hard 로 두면 합격본이 실패한다.
- **C 트루 피크만 코드 수정** — mux loudnorm 을 2패스(측정 → linear)로 바꿔 TP 를 맞춘다. final.mp4 음성 샘플이 바뀐다(mix.f32 는 무변경). 음악 레벨은 A 또는 B 와 함께 정해야 한다.

권고 근거: 판정 ①(규칙 값 두 개, 되돌릴 수 있음) ③(저장소 실측·사용자 판정 이력 우선). 10 §3 "bed_gain 0.47 = 사용자 합격, 바꾸지 않는다"와 같은 원칙 — 합격본을 실패로 만드는 임계는 규칙 쪽이 틀렸다. 단 **13 수치를 바꾸는 것은 사용자 합격 기준의 해석**이라 §7 사용자 고유 결정에 해당하는지 판단을 부탁한다.

## 쟁점 2 — 문장 간 음량 편차(작업 7, `reports/phase8/sentence_rms.json`)
믹서처럼 문장마다 피크 정규화(0.8) 뒤, 무음 제외 RMS:
- 45문장 평균 −16.08 dB, **표준편차 0.65 dB, 범위 2.83 dB**(최저 debate_1 −17.65, 최고 now_0 −14.82), 평균에서 3 dB 넘게 벗어난 문장 0.

### 선택지
- **A(권고) 정규화 없음(현행 피크 정규화 유지) + 오디오 QA warning 한 줄**: 문장 RMS 가 평균에서 3 dB(규칙) 넘게 벗어나면 경고. 지금 v3 는 0건. ElevenLabs 전환(10 §7-4) 때 다시 잰다.
- **B 문장별 RMS 정규화 옵션**(규칙 `audio.sentence_norm: peak|rms`, 기본 peak) — 기본값이면 mix 무변경. 쓰일 근거(편차 큰 음성)가 아직 없다.
- **C RMS 정규화를 기본값으로** — v3 mix 가 바뀐다(합격 음량 유지 조건 위반).
