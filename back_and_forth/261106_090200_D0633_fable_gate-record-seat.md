# 지시 — 사용자 게이트 승인은 감독 세션에서 기록한다(UF-267 재발 방지). 칸나이 전달 뒤 첫 작업

## 0. 사용자 원문
- UF-266 "영상 내놔"
- UF-267 "칸나이 게이트 ② 프리뷰 승인. 기록하고 720p 전편 진행해. 라고 보냈어. 내가 너한테만 교신하면 되는데 왜 이렇게 됐지? 재발 방지해"

## 1. 원인(PIPELINE-AP-027)
- 사용자 승인(UF-265)은 감독 세션에 왔다. D-0632 가 기록을 구현 세션에 맡겼다.
- 구현 세션 권한 장치는 그 세션에 사람이 직접 친 승인만 받는다. 세션 사이 메시지는 사람 입력이 아니다. 이것은 정상 동작이다.
- 감독은 막힌 뒤 길을 고치지 않고 사용자에게 세션 이동을 요청했다. 약 7시간 멈췄다.

## 2. 규칙(지금부터, README §9 "게이트 승인 기록 자리")
- 사용자의 교신 창구는 감독 세션 하나다. 사용자 게이트 승인은 감독 세션에서 `approve` 로 기록하고 push 한다.
- 구현 세션은 사용자 승인을 대신 기록하지 않는다. 기록된 승인을 pull 해서 진행만 한다.
- 권한 장치를 넓히거나 우회하지 않는다.

## 3. 만들 것(칸나이 완성본 전달 뒤 첫 작업, 기한 = 다음 영상 게이트 ① 전)
1. **gate packet**: 게이트 자료를 올릴 때 승인 검사 입력을 git 추적 파일로 함께 둔다. 예: `projects/{pid}/gate_packet.json`(schema_version 1, Pydantic 모델).
   - 담을 것: 콘티 판 provenance 요지(total_sec·원고 sha1·만든 시각), plan 길이, 원고 sha1, 자산 승격 상태(pending 초상·휘장 수), 만든 세션·커밋.
   - 파일 지문(sha1)을 담아 바꿔치기를 막는다.
2. **approve 경로**: `out/` 가 없는 작업 트리(감독 컨테이너)에서는 require_animatic·require_asset_library 가 gate packet 을 읽어 같은 판정을 한다. packet 이 없거나 지문이 어긋나면 거부한다. 우회 플래그 없음.
3. **진행 경로**: 구현 세션은 pull 한 project_manifest.json 의 승인 기록을 확인하고 진행한다. post_approval 류 스크립트의 0단계가 이것이다.
4. **시험**: (가) out/ 없는 임시 작업 트리에서 packet 으로 게이트 ② 승인이 기록된다. (나) packet 지문이 어긋나면 거부. (다) packet 의 원고 sha1 이 현재 원고와 다르면 거부. (라) 기존 out/ 경로 판정은 그대로.
5. 원장 UF-266·UF-267 guards 에 시험·코드 ref 를 단다(감독이 확인 뒤).

## 4. 하지 않는 것
- 구현 세션 권한 규칙에 approve 허용을 넣지 않는다(사람 승인을 AI 가 기록하는 길을 여는 것).
- 감독 세션이 사용자 원문 없이 approve 를 실행하지 않는다. `--comment` 에 사용자 원문과 UF 번호를 그대로 적는다.
