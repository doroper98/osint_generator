# UF-99(재발, recurs_of UF-02·UF-97) — 카메라 꺾임의 진짜 원인: 화면 단계 경계 클램프. 검사는 클램프 전 궤적을 쟀다

사용자 원문(2026-10-12, v6.0.2 시청): "여전히 지도에서의 카메라 무빙에 있어서 한번 꺾이는 지점이 있어. 이거 이전에도 코멘트 했고 계속 코멘트 하는데 개선이 안되네? 영상을 새로 제작할 필요는 없는데, 규칙 점검해서 다시는 발생하지 않도록 적어놔"
→ **영상 재제작 없음.** 규칙·검사·시험만 고친다. 원장 UF-99(status open, 감독이 기록함).

## 0. 감독 실측(완성 영상 그대로 — `artifacts/gulf_pact_2026-v6.0.2` final_720p.mp4)
방법: 프레임 사이 광류(LK)로 화면 닮음 변환(이동·배율)을 재고, 배율 변화의 **고정점**(화면에서 멈춰 있는 점)을 구했다.
fixed_point 경로라면 이동 한 번 동안 고정점은 한 점이어야 한다.

| 시각 | 실측 | 뜻 |
|---|---|---|
| 29.71초 | 축소 중 고정점 x +390px → **−320px(화면 왼쪽 끝)** 한 프레임 만에 이동. 가로 흐름 +6.8 → −5.6 px/프레임 **방향 반전** | 화면 왼쪽 끝이 `stage.bounds` xmin 에 닿아 x0 가 잘림 |
| 30.04초 | 줌 −0.41/초 → **0**(한 프레임), 세로 이동만 남음 | w 가 경계 폭 상한에 닿아 잘림 |
| 61.67초 | 세로 이동만 하다 줌 0 → **+0.44/초 한 프레임에 시작**(이징 없이), 고정점 왼쪽 끝 | 위의 역순(확대 시작 시 클램프 풀림) |
| 62.67초 | 고정점 왼쪽 끝 → 화면 안쪽으로 점프 | x 클램프 풀림 |
| 132.50·132.92초 | 29.7초와 같은 꼴(고정점 왼쪽 끝으로, 이어 줌 0) | 같음 |
| 288.62·288.96초 | 같은 꼴, 가로 흐름 +11.8 → −12.9 px/프레임 | 같음 |
| 300.38초 | 61.67초와 같은 꼴(줌 +0.29/초 즉시 시작) | 같음 |

원인 코드: `engine/projection.py View.__init__` — `w = min(w, xmax-xmin-0.01, …)`, `x0 = min(max(x-w/2, xmin), xmax-w)`, `y1` 같은 꼴.
연속 함수지만 **꺾이는(미분 불연속) 함수**다. 넓게 빠지는 이동이 경계에 닿는 순간 속도가 한 프레임 만에 바뀐다.

**왜 장치가 못 잡았나(재발의 뿌리):** `camera_continuity`·`camera_speed`·SK-C1 은 모두 `P.cams`(= `build_camera` 출력, **클램프 전 요청 궤적**)를 잰다.
사용자가 보는 것은 `View` 가 자른 뒤의 궤적이다. 재는 것 ≠ 보이는 것. UF-02 → 5차 이징(D-0202) → UF-97 속도 상한(D-0216) 모두 요청 궤적만 고쳤고,
꺾임은 요청 궤적에 없었으므로 검사는 계속 통과했다.

## 1. 지시(결정, Fable)
1. **측정 대상 교체(주입 아닌 교체, C11)**: 카메라 검사(`camera_continuity`·`camera_speed`·`camera_per_sentence` 등 카메라 궤적을 재는 모든 검사)와 스케치 SK-C1 은
   **화면에 실제로 쓰인 뷰**(View 적용 뒤의 x0·y1·w 에서 되돌린 중심·폭)를 잰다. 한 함수(예: `engine.camera.effective_track(stage, cams)`)로 만들고 렌더러·검사가 같은 것을 쓴다.
2. **새 hard 검사 `camera_bounds`**: 어느 프레임이든 요청 궤적과 화면 궤적이 다르면(클램프가 걸리면) hard 실패. 메시지에 시각·잘린 성분(x·y·w)·허용 최대 w 를 적는다.
   - 렌더러가 조용히 자르는 것도 P6(조용한 폴백) 위반이다. 클램프는 안전망으로 남기되 **걸리면 검사가 실패**한다.
3. **연출 쪽 예방**: 키 목표를 경계 안에서 고르게 한다 — `camera_suggest`·연출 프롬프트(규칙 파일에서 생성)·`frame_points` 가 경계 안의 w·중심만 제안. 
   근거: fixed_point 경로에서 (x, y, w) 는 이동 한 번 동안 직선 위에 있고, 경계 안 집합(w ≤ Wmax, xmin+w/2 ≤ x ≤ xmax−w/2 …)은 볼록이다 → **두 키가 경계 안이면 이동 전체가 경계 안**이다.
   드리프트·creep 은 w 를 줄이는 쪽이라 경계를 넘지 않는지 시험으로 확인한다.
4. **저장소 전체(C12-3)**: 본 엔진(콘티 판·프리뷰·전편)·스케치·차트 아일랜드(`engine/island.py` View)·시간축 무대 모두. 카메라를 화면 단계에서 바꾸는 다른 곳이 있는지 grep 으로 전수 확인해 보고(클램프·스냅·반올림).
5. **원칙 문장(규칙)**: `rules/video_rules.yaml` 에 한 줄 — "카메라 검사는 화면에 그려진 뷰를 잰다. 렌더 단계의 보정(클램프 등)이 걸리면 실패." `docs/handoff/15` 에도 같은 교훈을 P12 보강으로(값 복사 금지, 규칙 키 인용).
