# V2 게이트 — 참값(edge WordBoundary)이 실제 음성보다 약 100ms 이르다. 게이트 기준 결정 요청

## 1. 쟁점
D-0164 §5-6 게이트는 "edge `WordBoundary` 참값 ↔ 강제 정렬, 어절 첫 글자 오차 중앙값 ≤ 60ms · p90 ≤ 120ms" 입니다.
시제품 측정(호르무즈 45 + fed 48 = 93문장, 851어절)에서 **raw 중앙값 109ms · p90 267ms** 로 미달입니다.
그런데 원인이 정렬기가 아니라 **참값 쪽의 계통 오차**로 보입니다. 미달 시 지침은 decision_request(후보 B faster-whisper)이고 임의 완화는 금지라, 근거와 함께 올립니다.

## 2. 근거(측정 — `reports/phaseV2/gate_rows_prototype.json`, 행 = 프로젝트·문장·어절·edge 시각·무음 보정 시각·MMS 시각·문장 정렬 시간)
| 측정 | 결과 |
|---|---|
| 문장 첫 어절 | edge 경계는 거의 모든 문장에서 **0.100초**(고정값처럼), 실제 음성 시작(10ms RMS 문턱)은 **0.37~0.46초**. MMS 첫 어절 ≈ 실제 시작 |
| 부호 있는 오차(MMS − edge) | 851어절 중 **음수 0개**. 20ms 구간 히스토그램: 80~120ms 에 452개(53 %), 60~160ms 에 85 %. 200ms 이상 꼬리 = 쉼표·문장 앞 등 **쉼 뒤 어절** |
| 쉼 뒤 어절(edge 시각이 무음 안 → 다음 발화 시작으로 보정, 197어절) | MMS ↔ 실제 발화 시작: **중앙값 21ms · p90 51ms**(부호 중앙값 −7ms). 참값을 독립적으로 알 수 있는 곳에서 MMS 는 게이트 안 |
| 문장 안 어절(654어절) | MMS − edge 부호 중앙값 **+102ms**, p90 138ms — 일정한 치우침 |
| 성능 | 모델 로드 10~11초(프로세스당 1회), 문장당 정렬 0.92초(CPU 4코어), 가중치 1,262,047,414 B |

해석: edge 의 WordBoundary 는 (a) 문장 시작을 0.1초에 고정하고 (b) 쉼 앞에서 경계를 쉼 시작에 두며 (c) 문장 안에서도 실제 발화보다 약 100ms 이르게 보고합니다. MMS 는 독립 참값(무음 뒤 발화 시작)과 21/51ms 로 맞습니다.
부수 영향(기록): 지금 골든의 `at_word` 앵커는 edge 정렬이라 실제 발음보다 약 0.1초(쉼 뒤는 0.3초 안팎) 이르게 걸려 있습니다. V3 에서 Supertonic + MMS 로 바뀌면 앵커가 그만큼 늦어집니다.

## 3. 선택지

## 4. 권고
**A**. 덧붙여 V2 run_log 에 edge 치우침 측정을 그대로 남기고, 사람 청취 표본(쉼 없는 문장 안 어절 10개, 앵커 시각에 클릭음)을 시트로 만들어 V3 청취 때 사용자 확인에 씁니다.
